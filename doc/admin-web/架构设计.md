# admin-web 整体架构设计

本文档描述 `apps/admin-web` 后台管理前端的当前实现与约定，便于后续扩展与协作。

## 1. 定位与目标

- **定位**：多站点平台的后台管理端（总后台与站点运营能力入口）。
- **目标**：响应式壳层（侧栏 + 顶栏 + 主内容区）、模块化路由、可独立下线的功能包、国际化与工程规范统一。

## 2. 技术栈

| 类别 | 选型 |
|------|------|
| 运行时 | React 19、TypeScript |
| 构建 | Vite 8、`@vitejs/plugin-react` |
| 样式 | Tailwind CSS v4、`@tailwindcss/vite` |
| 路由 | `react-router-dom` |
| 服务端状态 / 请求 | `@tanstack/react-query`、预留 `axios` |
| 轻量客户端状态 | `zustand`（如侧栏开关） |
| 反馈 | `sonner`（全局 Toast） |
| 国际化 | `i18next` + `react-i18next` |
| 工具类 | `clsx`、`tailwind-merge`（`cn`）、`lucide-react`（图标） |

## 3. 目录与职责（高层）

```text
apps/admin-web/src/
  i18n/                 # 仅全局公共文案与资源装配
  layouts/              # 布局壳（按子目录拆分）
  navigation/           # 侧栏结构、路径解析（无具体文案）
  components/page/      # 页面级通用块（勿在 components 根目录平铺）
  pages/<模块>/         # 业务页面 + 该模块 locales
  lib/                  # 与 UI 无关的工具（如 cn）
  stores/               # 全局轻状态
```

路径别名：**`@/` → `src/`**（`vite.config.ts` 与 `tsconfig.app.json` 的 `paths` 已配置）。

## 4. 布局架构（Admin Shell）

后台采用 **「移动端抽屉侧栏 + 桌面固定侧栏」** 与 **顶栏 + 主内容区** 组合，代码按文件拆分，避免单文件臃肿。

| 文件 | 职责 |
|------|------|
| `layouts/admin/admin-layout.tsx` | 组合壳层与 `<Outlet />` |
| `layouts/admin/admin-mobile-backdrop.tsx` | 小屏遮罩与关闭侧栏 |
| `layouts/admin/admin-sidebar.tsx` | 分组导航、折叠逻辑 |
| `layouts/admin/admin-header.tsx` | 标题、搜索占位、语言切换 |
| `layouts/admin/index.ts` | 对外导出 `AdminLayout` |

**推荐引用方式**：

```ts
import { AdminLayout } from '@/layouts'
// 或
import { AdminLayout } from '@/layouts/admin'
```

## 5. 路由与信息架构

- **入口**：`App.tsx` 中嵌套路由，`AdminLayout` 为父级，子路由渲染于主内容区。
- **当前模块路径**（与侧栏一致）：
  - `/dashboard` — 数据概览
  - `/apps/style` — 风格设置（「我的应用」下）
  - `/config/params` — 参数配置（「配置设置」下）
  - `/analytics`、`/team`、`/system` — 数据分析、人员管理、系统设置
- **兼容重定向**：旧路径如 `/sites`、`/templates` → `/apps/style`；`/reservations` → `/analytics`；`/ai`、`/settings` → `/system`（便于书签与历史链接）。

侧栏配置见 `navigation/menu.ts`（**结构 + `labelKey`**，不写死中文）；`navigation/nav-path.ts` 提供路径匹配工具；`resolveNavTitleKey` 用于顶栏标题键解析。

## 6. 国际化（i18n）架构

### 6.1 原则

- **`src/i18n/` 仅承载全局公共模块**：`common`、`layout`、`nav`（壳层、导航键、空状态引导等）。
- **具体页面的文案放在 `pages/<模块>/locales/`**，与业务同目录，删除功能时可连同路由、`page-namespaces` 注册一并移除，降低耦合。

### 6.2 默认语言与持久化

- **默认展示语言**：日语（`ja-JP`）。无本地存储且浏览器语言无法匹配时，回落到 `DEFAULT_LOCALE`（见 `i18n/constants.ts`）。
- **语言持久化**：`localStorage` 键 `admin-web.locale`（`detect-locale.ts` 读写）。

### 6.3 全局资源装配

- `i18n/resources.ts`：合并各语言的 `common` / `layout` / `nav` 与 **页面命名空间**。
- `i18n/page-namespaces.ts`：维护页面级命名空间列表及 `pageNamespacesFor(locale)`；**新增或下线模块时需改此文件**（与对应 `pages/*/locales` 同步）。

### 6.4 页面命名空间（当前）

| 命名空间 | 文案目录 |
|----------|-----------|
| `dashboard` | `pages/dashboard/locales/` |
| `styleSettings` | `pages/apps/locales/` |
| `paramsConfig` | `pages/config/locales/` |
| `analytics` | `pages/analytics/locales/` |
| `team` | `pages/team/locales/` |
| `systemSettings` | `pages/system/locales/` |

各模块惯例：`zh-CN.ts`、`en-US.ts`、`ja-JP.ts` + `index.ts` 导出聚合对象（如 `DASHBOARD_LOCALES`）。

## 7. 组件规范

- **`components/page/`**：页面级通用块（如 `PageHeader`、`StatCard`、`EmptyModulePage`），通过 `components/page/index.ts` 统一导出。
- **禁止**在 `components/` 根目录随意堆叠业务组件；后续可按需增加 `components/ui/`（原子组件）等子目录。

`EmptyModulePage` 使用 **`namespace`** 指向上述 i18n 命名空间；占位引导语使用全局 **`layout.emptyModule.initLead`**。

## 8. 与后端的约定（规划）

`admin-web` 是多站点平台的后台管理前端，主要调用 `site-service` 完成站点业务管理。

- `admin-web` 主要调用 `site-service`：
  - 站点管理
  - 模板管理
  - 页面管理
  - 预约管理
  - 知识库管理
  - 文件管理
  - 数据统计
  - 系统配置
  - 用户、角色与权限管理

- `admin-web` 在 AI 调试或运营场景下调用 `agent-service`：
  - Prompt 测试
  - 模型连接测试
  - AI 对话测试
  - SSE 流式响应调试

- `agent-service` 后续通过内部接口调用 `site-service`：
  - 获取站点配置
  - 获取知识库内容
  - 获取行业 Prompt
  - 保存 AI 聊天记录
  - 必要时创建预约草稿

## 9. 新增 / 下线功能检查清单

**新增模块**

1. `pages/<模块>/` 下增加页面与 `locales/`（三种语言 + `index.ts`）。
2. 在 `i18n/page-namespaces.ts` 中注册命名空间并在 `pageNamespacesFor` 中挂载。
3. 在 `navigation/menu.ts` 中增加路由与 `labelKey`；在 `App.tsx` 中注册路由。
4. 在 `i18n/locales/*/nav.ts` 中补充对应 `labelKey` 翻译。

**下线模块**

1. 删除路由与 `pages/<模块>/`。
2. 从 `page-namespaces.ts` 移除对应命名空间与 import。
3. 清理 `menu.ts` / `nav` 文案键中不再使用的条目。
