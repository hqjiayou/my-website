# admin-web 页面与模块开发规范

本文汇总当前仓库已落地的约定（路由重构、命名、列表页基建、权限、样式分层等）。**不确定能否做时，先查本文对应章节。**

---

## 1. 文件命名

### 1.1 默认规则：camelCase（首字母小写驼峰）

| 类型 | 示例 |
|------|------|
| 页面 | `permissionListPage.tsx`、`loginPage.tsx` |
| API | `authApi.ts`、`rbacApi.ts` |
| Store | `authStore.ts`、`adminPreferencesStore.ts` |
| 工具 / 类型 | `apiError.ts`、`menu.ts`、`rbac.ts` |
| 路由配置 | `routePaths.ts`、`appRoutes.tsx`、`authGuard.tsx` |
| 组件（单文件） | `dataTable.tsx`、`adminPageHeader.tsx` |
| Hooks | `useDebounce.ts`、`usePermission.ts` |

### 1.2 固定例外（保持原名）

| 文件 | 原因 |
|------|------|
| `index.ts` / `index.tsx` | barrel / 目录入口 |
| `main.tsx`、`App.tsx` | 应用入口 |
| `zh-CN.ts`、`en-US.ts`、`ja-JP.ts` | 区域语言文件名 |

### 1.3 禁止

- kebab-case 文件名：`permission-list-page.tsx`、`auth-api.ts`
- 无意义缩写根目录文件：`Paths.ts`、`Routes.tsx`（应用 `config/routePaths.ts`、`routes/appRoutes.tsx`）
- 在 `router/index.tsx` 中 barrel 再导出 `ROUTES`、`permission`（易循环依赖）

### 1.4 组件导出命名

- 文件名 camelCase，**导出名**仍用 PascalCase：`export function PermissionListPage()`
- 页面默认导出一个主组件，名称与业务一致：`XxxPage`

## 2. 目录结构（边界）

```
apps/admin-web/src/
├── api/                 # 按域分子目录；页面只从 @/api 或 @/api/xxxApi 引入
├── assets/styles/       # 仅全局三层：globals / theme / font（见 §8）
├── components/
│   ├── admin/           # 后台通用列表/表单基建（见 §9）
│   └── page/            # 轻量页面壳：PageHeader、StatCard 等
├── config/              # 如 preferences.ts（本地偏好）
├── hooks/               # 跨页 hooks
├── i18n/                # 全局 common/layout/nav + namespaces 注册
├── layouts/             # AdminLayout 壳；components/header|sidebar|mainContainer
├── pages/<domain>/      # 业务页 + 可选 locales/、components/
├── router/              # 见 §7
├── stores/              # Zustand：auth、偏好、layout 等
├── types/               # 共享 TS 类型（如 rbac.ts）
└── utils/               # 纯工具；http/ 为请求封装
```

**边界：**

- 页面逻辑放在 `pages/`，不要堆进 `layouts/` 或 `router/`
- 侧栏菜单数据：`utils/menu.ts` 转接口 `menus`；静态顶栏标题键：`router/navigation/`
- 单页专属 UI（如登录海洋背景）可写在**同一页面文件**内私有组件，不必强行拆文件，除非复用

## 3. 页面组织

### 3.1 放置与拆分

- 路径：`src/pages/<domain>/`
- 一功能一页一文件为主：`permissionListPage.tsx`
- 可增子目录：`locales/`、`components/`、`hooks/`（仅本域使用）
- 复杂列表/表单逻辑过长时，再拆同级 `components/`，避免单文件失控

### 3.2 注释

- **除 `.tsx` 外**，新建/大改的文件首行加功能注解（单行 `>` 或 `/** */`）
- `.tsx` 内仅对非显而易见业务规则写简短注释

### 3.3 特殊页：登录

- `loginPage.tsx`：表单 + 海洋像素背景可**同文件**内聚（`LoginOceanBackground` 等私有函数）
- 背景无外部图片依赖时，保持纯 CSS / 内联 `<style>`，不放入 `assets/styles/`

## 4. 列表页标准（模板）

**参考实现：** `src/pages/permissions/permissionListPage.tsx`

新做「查询 + 表格」管理页时，按此组合拼装，避免重复造轮子：

| 能力 | 使用 |
|------|------|
| 页头 | `AdminPageHeader`（`@/components/admin`） |
| 筛选 Tab | `FilterTabs` |
| 搜索 / 刷新 | `SearchToolbar` + `useDebounce(keyword, 300)` |
| 表格 | `DataTable` + `DataTableColumn<T>` |
| 状态展示 | `StatusTag`、`CopyableText`（按需） |
| 客户端分页 | `useClientPagination`（数据量在前端过滤时） |
| 文案 | `useTranslation('<pageNamespace>')` + `common` |
| 错误 | `isApiError` + `refetch`；Query 默认 mutation 错误走 `handleApiError` |

### 4.1 数据请求

```ts
const { data, isPending, isError, error, refetch, isFetching } = useQuery({
  queryKey: ['permissions'], // 语义化 key，含参数时把参数放进 key
  queryFn: () => rbacApi.listPermissions(),
})
```

- **禁止**在页面内直接 `axios` 或 `fetch`
- **禁止**页面 import `@/mocks/*`（API 层内部可接 mock）

### 4.2 React 写法

- 避免在 `useEffect` 里同步 `setState` 做「派生重置」（eslint `react-hooks/set-state-in-effect`）
- 推荐：`useMemo` 派生、子组件 `key` 重置、或 `useWatch`（react-hook-form）替代 `watch()`

## 5. API 与 HTTP

### 5.1 引入方式

```ts
// 优先：具体模块（tree-shaking 清晰）
import { rbacApi } from '@/api/rbacApi'

// 或：barrel（仅当已导出）
import { siteApi } from '@/api'
```

### 5.2 HTTP 栈

| 模块 | 职责 |
|------|------|
| `utils/http/axios.ts` | 实例、401 与 `authStore` 打通 |
| `utils/http/apiError.ts` | `ApiError` 类型 |
| `utils/http/handleApiError.ts` | toast 等统一错误展示 |
| `utils/http/unwrap.ts` | 解包后端统一响应 |
| `utils/http/queryClient.ts` | 全局 QueryClient 默认项 |

页面层只关心 `apiXxx` 方法与 `isApiError`，不拼装 baseURL。

## 6. 路由与权限（必读）

详见 `src/router/README.md`；此处只写**边界**。

### 6.1 目录

```
router/
├── index.tsx              # 仅导出 AppRouter（含 SessionBridge）
├── config/routePaths.ts   # ROUTES 常量，零依赖
├── routes/
│   ├── appRoutes.tsx      # 守卫 + Routes 根
│   ├── adminRoutes.tsx    # 业务 Route 片段（新页主要改这里）
│   └── legacyRedirects.tsx
├── guards/                # guestGuard / authGuard / permissionGuard
├── permission/            # RBAC：constants、utils、hooks、gate
└── navigation/            # 静态 NAV、resolveNavTitleKey
```

### 6.2 接口菜单 vs 静态路由

| 来源 | 管什么 | 不管什么 |
|------|--------|----------|
| `auth/me` → `menus` | 侧栏**显示**哪些入口 | 不注册 React Router |
| `auth/me` → `permissions` | 按钮/路由**能否访问** | 不决定用哪个页面组件 |
| `routes/adminRoutes.tsx` | path → 页面组件 | **必须手写** `<Route />` |
| `permission/constants.ts` | 部分 path → 权限码 | 与接口 permissions 配合 |

**新增菜单页 checklist：**

1. `config/routePaths.ts` 增加 path
2. `routes/adminRoutes.tsx` 增加 `<Route />` + `handle.titleKey`（如需）
3. 后端菜单种子的 path 与上一致
4. 若需路由级鉴权：在 `permission/constants.ts` 配置 `ROUTE_PERMISSIONS`

### 6.3 导入约定

```ts
import { ROUTES } from '@/router/config/routePaths'
import { resolveNavTitleKey } from '@/router/navigation'
import { PermissionGate, useHasPermission, CanAccess } from '@/router/permission'
import { AppRouter } from '@/router' // 仅 App.tsx
```

```ts
// 禁止
import { ROUTES } from '@/router'
```

### 6.4 模块职责

| 模块 | 职责 |
|------|------|
| `stores/authStore` | token、用户、menus、permissions **数据** |
| `router/permission/` | 权限**判定**、`PermissionGate` / `CanAccess` |
| `router/guards/` | 路由**拦截** |
| `router/routes/` | 页面**注册** |

## 7. 权限在页面中的用法

```tsx
import { PermissionGate, useHasPermission } from '@/router/permission'
import { PERMISSION_CODES } from '@/types/rbac'

const canCreate = useHasPermission(PERMISSION_CODES.roleCreate)

<PermissionGate code={PERMISSION_CODES.roleCreate}>
  <button>新建</button>
</PermissionGate>
```

- 路由无权限：由 `permissionGuard` 展示 `forbiddenPage`
- 按钮/区块：用 `PermissionGate` 或 `CanAccess`（支持 `anyOf` / `allOf`）
- 菜单可见性：接口 + `canShowMenu`（侧栏构建时）

## 8. 样式与主题

全局样式**仅** `src/assets/styles/` 三层（`globals.css` → `theme.css` / `font.css`）。

| 场景 | 放哪 |
|------|------|
| 单页/单组件样式 | 组件内 Tailwind，或页面旁 CSS Modules |
| 全站 token、暗色、密度、主色 | `theme.css` |
| 全站字号 | `font.css` |
| 偏好写入 DOM | `config/preferences.ts` → `data-*` / `.dark` |

**禁止：**

- 在 `assets/styles/` 下新建 `pages/xxx.css`、业务名 css
- 页面 `import '@/assets/styles/xxx.css'`（除入口已引的 globals）

入口仅 `main.tsx`：`import '@/assets/styles/globals.css'`

## 10. 国际化（i18n）

### 10.1 全局

- `i18n/constants.ts`、`resources.ts`：`common` / `layout` / `nav`
- 区域文件：`locales/<locale>/common.ts` 等（**小写**文件名）

### 10.2 页面

- 每域 `pages/<domain>/locales/`：`zh-CN.ts`、`en-US.ts`、`ja-JP.ts` + `index.ts`
- 在 `i18n/namespaces.ts` 注册 namespace 与 `pageNamespacesFor`
- 页面内：`useTranslation('permissions')`，通用按钮等用 `useTranslation('common')`

### 10.3 路由标题

- `adminRoutes.tsx` 的 `handle={{ titleKey: 'items.xxx' }}` 对应 `nav` 命名空间
