# 模块职责与依赖边界

> **文档状态**：当前有效  
> **对应阶段**：4F  
> **当前适用性**：与根 `pom.xml`、各模块 `pom.xml` 一致；实施新依赖前请对照下表。  
> **最近同步**：2026-05-23  

---

## 单模块内部结构 ≠ Maven 模块边界

- **Maven 模块**（gateway、auth、admin…）表达 **进程与依赖**边界。  
- **包结构**（`controller` / `service` / `service.impl` / `dto`…）表达 **单模块内职责**；**仅适用于业务模块**（admin、auth、site-core、site-app）。  
- **gateway / common / infra / agent 不套用业务模块标准树**。  
- **Cursor / AI 开发必读**：[单模块文件结构与AI开发约束规则V1.md](../设计文档/基础架构/单模块文件结构与AI开发约束规则V1.md)

| 归属 | 说明 |
|------|------|
| **auth** | 认证基座；**不**做 RBAC/菜单管理 |
| **admin** | 后台业务与 **RBAC/菜单（5E）管理**、Resource Server 验签 |
| **gateway** | 路由与横切；**不**判权、**不**聚合 Swagger |

## 模块总表

| 模块 | 是否独立 Spring Boot 进程 | 主要职责 | 可以依赖 | 不应 / 禁止依赖 |
|------|---------------------------|----------|----------|------------------|
| **gateway** | 是 | 路由、CORS、请求维度的横切；**唯一网关口** | 仅限 Gateway / Reactor 相关（参见该模块 `pom.xml`） | **业务模块**（admin、auth、site、common 中的业务 DTO）、**数据库/Redis** 直连 |
| **auth** | 是 | 统一认证；Admin 与 Site 登录/刷新/登出；JWT **签发**（**RS256 + JWKS**）；Redis Refresh 会话 | `common`、`infra` | **`admin` / `site-*` 业务 JAR**（不反向依赖业务服务） |
| **admin** | 是 | 后台 **Resource Server** + **业务 API**；Flyway 执行方之一 | `common`、`infra`、`agent` | **`auth` 内部实现包**；跨服务只认 **`common.security` + HTTP 契约** |
| **site-app** | 是 | 站点 HTTP 入口；装配 site-core 与空模块 site-car / site-cake | `common`、`infra`、`agent`、`site-core`、`site-car`、`site-cake` | 与 admin 模块 **强耦合** |
| **site-core** | 否（jar） | 站点域公共能力与实体/Mapper 归属 | `common`、`infra` | 把单个站点的业务写进 core |
| **site-car / site-cake** | 否 | 空模块，无业务代码 | `site-core` | 彼此依赖 |
| **common** | 否 | 通用响应、错误模型、**common.security 契约** | 仅 JDK/极少数纯工具依赖（见 `pom`） | **`admin` / `auth` / `site` 业务** |
| **infra** | 否 | 存储、缓存、MyBatis-Plus、i18n 底座、JWT 条件装配等 | `common` | **业务模块**、业务实体 |
| **agent** | 否 | 对外 Agent HTTP 客户端 | `common`（及允许的轻量依赖） | **`infra`**（当前不直连库；若未来需要则由上层编排） |

---

## 约束说明（摘要）

1. **admin 不依赖 auth 内部实现**：验签与身份模型走 **`common.security`**；令牌签发于 **auth** 进程。  
2. **auth 不依赖 admin 业务**：可共读 **`admin_user` 等表**（同 schema），表映射在 **auth 自有** `entity`/`mapper`，**Maven 不依赖** `admin` 模块。  
3. **common / infra 不依赖业务模块**，避免循环与污染通用层。  
4. **gateway 不承载业务规则**、不在此实现鉴权业务（各服务 Resource Server 自行验 JWT）。  
5. **site**：**当前**以单一 `site-app` 为主；**未来**多门户/多实例时仍复用 **site-core** 与 **gateway** 路由扩展，**不在 4F** 强拆多进程。
