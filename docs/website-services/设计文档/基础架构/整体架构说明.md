## 1. 项目定位

`my-website` 是一个多站点网站合集平台，目标是用一套平台能力支持多个行业站点，例如汽车维修、蛋糕烘焙，后续也可以扩展到美容院、诊所、中古车店等场景。

平台分为三类能力：

- 前台站点：面向访客，展示行业站点内容并提供咨询、预约等入口。
- 后台管理：面向运营/管理人员，管理站点、模板、配置、内容、文件、预约与数据。
- 后端服务：统一网关、后台 API、前台 API、基础设施接入、AI/Agent 客户端与未来业务模块。

## 3. 子系统职责

### 3.1 apps/admin-web

后台管理前端，负责多站点平台的管理界面。

主要职责：

- 站点管理
- 模板与页面配置
- 内容、文件、预约管理
- AI 知识库与 Prompt 管理
- 数据统计与系统设置

专项文档：

- `docs/admin-web/架构设计.md`
- `docs/admin-web/API设计.md`

### 3.2 apps/site-web

前台站点集合目录，按行业拆分不同前台应用。

当前包含：

- `car-web`：汽车维修行业站点
- `cake-web`：蛋糕烘焙行业站点

前台站点主要通过后端 `gateway` 访问前台 API，后续也可接入 AI 咨询、预约、站点公开配置等能力。

### 3.3 services/website-services

Java 后端多模块工程，当前是后端主干服务。

**可执行 Spring Boot 应用**：

- **`gateway`**：统一 API 网关，端口 **8080**
- **`auth`**：统一认证服务（**4F**），端口 **8083**（`AUTH_APP_PORT`）
- **`admin`**：后台管理 API，端口 **8081**（**Resource Server** + 业务）
- **`site/site-app`**：前台站点 API，端口 **8082**

**库模块（摘要）**：

- `common`：通用响应、错误码、**`common.security`** 身份/JWT 轻量契约
- `infra`：PostgreSQL、Redis、MinIO、MyBatis-Plus、**系统消息 i18n** 底座
- `agent`：对接 **agent-services** 的 Java 客户端层
- `site/site-core`：站点域公共能力与实体归属；**未来多门户/多行业站点**复用该核心，而非逐站重复造用户体系

**已不再作为 Maven 模块**：顶层 **`config`**（4F 已移除）。

### 3.4 services/agent-services

**Python 3.13 + FastAPI + Pydantic AI V2** 的 AI Execution Runtime（internal only，端口 **3001**）。Java owns business truth，Python owns AI execution（ADR-0005）。

- Java `agent` 模块的 `HttpAgentClient` 经内网调用 `/internal/v1/*`（需 `X-Internal-Service-Token`）
- **不经 gateway 暴露**；公开探活仅 `GET /health`
- 无 `AI_MODEL`/凭证时诚实 BLOCKED（ADR-0004）；`AGENT_INTERNAL_SERVICE_TOKEN` 缺失则启动 fail-fast

详见 [`services/agent-services/README.md`](../../../../services/agent-services/README.md) 与设计文档 [`Agent服务技术选型与架构设计V1.md`](../AI/Agent服务技术选型与架构设计V1.md)。

## 4. 后端调用关系

推荐请求路径：

```text
admin-web ─┐
           ├──> website-services/gateway:8080 ──> /api/auth/**              → auth:8083（登录 / 刷新 / 登出等）
           │                                 ──> /api/admin/**（业务）     → admin:8081（含 **`GET /api/admin/auth/me`**）
site-web  ─┘                                 └──> /api/site/**             → site-app:8082（含 **`GET /api/site/auth/me`**）
```

**现行契约**：详见 **[`services/website-services/README.md`](../../../../services/website-services/README.md)** §认证 HTTP 契约。**JWT**：载荷 **`subject_type`** 为 **`SubjectType`**（与 **`aud`** 语义分离）；**`auth`** 内解析时作 **枚举比对**。

**4F 后**：认证编排与业务 **进程分离**；**外部统一入口**仍为 **Gateway**。内部实现要点见 **[架构设计](./架构设计.md)**。

内部依赖（Maven 聚合意图，**非 HTTP 调用链**）：

```text
site-app / admin
  ├── infra  -> PostgreSQL / Redis / MinIO
  └── agent  -> services/agent-services
auth
  ├── common
  └── infra
```

当前阶段不引入注册中心、服务发现、消息队列或 **网关内业务级鉴权**。`gateway` 只做统一入口、CORS、路由与基础横切。

## 5. 数据与用户模型边界

后台用户体系归 `admin`：

- `admin_user`
- `admin_role`
- `admin_permission`
- `admin_user_role`
- `admin_role_permission`

前台用户体系归 `site/site-core`：

- `site_user`
- `site_user_profile`
- 可选扩展 `site_user_auth`

前台多站点用户统一使用 `site_user`，通过 `site_id` 或 `site_code` 隔离不同站点。不要为不同业务站点分别创建 `car_user`、`cake_user`。

**当前代码态**：**`/api/auth/*`**（登录 / 刷新 / 登出）由 **`auth`** 实现；**`GET /api/admin/auth/me`**、**`GET /api/site/auth/me`** 分别在 **`admin`**、**`site-app`**（Resource Server）；**Access JWT 校验**在上述业务进程中完成。详见 **`README`** §认证 HTTP 契约。

**路线图**：**4H / 4I** 已完成；下一阶段 **5A（RBAC）** —— [`总览/后端开发路线图与阶段状态.md`](../../总览/后端开发路线图与阶段状态.md)。

## 6. 本地基础设施

### 6.1 local-stack 与 `website-services/.env`

**本地 PostgreSQL / Redis / MinIO（AIStor）统一由既有 local-stack 提供**，典型映射：**`local-postgres` → `localhost:5432`**，**`local-redis` → `localhost:6379`**，**`local-aistor` → `localhost:9000`**。**本仓库不在 `website-services` 下再起第二套 Postgres/Redis Compose**。Java 应用在 **`services/website-services/.env`**（范本 `.env.example`）中对齐 JDBC / Redis / MinIO；与 **local-stack** 自带 Compose `.env` **分开维护**。

### 6.2 常见端口

本地后端常用端口：

- PostgreSQL：`localhost:5432`
- Redis：`localhost:6379`
- MinIO / AIStor API：`http://localhost:9000`
- MinIO / AIStor Console：以栈配置为准（常见 `9001`）

建议先启动本地基础设施，再启动 Java 后端服务。否则应用可启动，但 actuator health 中数据库或 Redis 可能显示 `DOWN`。

## 7. 推荐启动顺序

1. 启动 WSL + Docker 本地基础设施。
2. 启动 `services/website-services` 后端：

```bash
cd services/website-services
mvn clean install -DskipTests
mvn -pl auth -am spring-boot:run
mvn -pl admin -am spring-boot:run
mvn -pl site/site-app -am spring-boot:run
mvn -pl gateway spring-boot:run
```

3. 启动前端应用：

```bash
cd apps/admin-web
pnpm install
pnpm dev
```

```bash
cd apps/site-web/car-web
pnpm install
pnpm dev
```

```bash
cd apps/site-web/cake-web
pnpm install
pnpm dev
```

联调认证时 **需同时启动 `auth` 与 `admin`**。`gateway` 可在最后启动以便路由到已就绪的上游。
