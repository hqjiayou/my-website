# 后端包结构与命名规范 V1（website-services）

**适用范围：** `services/website-services/` 下全体 Java/Spring Boot 模块。  
**目标：** 以「Maven 界定业务边界 + 模块内常规职责目录」保持长期可维护，避免 **`auth`** / **`admin`** 再次按业务域名拆二级树、避免 **`dto` 多级子目录与混名**、避免 **`Outcome`/`Summary`/`Result`** 等与 **`RequestDto`/`ResponseDto`** 并行的多套口径漂移。  
**与阶段关系：** **不改**阶段 4A 认证技术方案边界；本节仅约束 **代码组织方式**。

> **AI / Cursor 必读（结构总纲）**：[单模块文件结构与AI开发约束规则V1.md](./单模块文件结构与AI开发约束规则V1.md) — Maven 模块边界、业务模块标准包树、**§3 文件名与目录职责匹配**、禁止中间层、**新增文件四问（含后缀校验）**。本文侧重 **命名后缀速查** 与 **common 边界**；与总纲冲突时 **以总纲为准**。

---

## 1. `common` 模块边界（最高优先级）

### 1.1 允许进入 `common` 的类型

仅限 **跨模块真复用**、且 **不包含具体业务契约** 的基础能力：

- 全局统一外壳：**`ApiResponse<T>`**
- 通用错误码 / 枚举：**`ErrorCode`**（及各模块共用的离散码值扩展方式）
- 通用异常：**`BusinessException`**（或对 `RuntimeException` 的薄封装基类）
- 通用分页 / 分页结果（若已形成稳定复用面）：本项目当前为 **`PageResult`**；若未来新增 **`PageRequest`**，须确有多模块消费再落 `common`
- 与业务无关的基础设施型工具（慎用）：需在文档与代码注释中写明 **被哪些模块复用**

### 1.2 禁止进入 `common` 的类型

**不得**下沉任何 **具体 REST 契约**：

- ❌ **`AdminPingResponseDto`** 等 **仅 admin 业务** 专有 DTO；**登录/刷新等认证契约**应放在 **`auth/dto`**（**4F**），而非 **`common`**

### 1.3 组合示例（正确）

返回类型 **`ApiResponse<AdminLoginResponseDto>`**：外层 **`ApiResponse`** 出自 **`common`**；**`AdminLoginResponseDto`** 出自认证服务（**`auth/dto`**，**4F**）。

## 2. 模块内一级目录（Spring Boot 职责）

以下 **一级包名** 为允许的常规目录（**按需存在**，不强求全齐）：

`config`、`controller`、`service`、`mapper`、`entity`、`dto`、`handler`、`security`、`exception`、`utils`、`properties`、`constant`、`filter`、`interceptor`、`context`。

### 2.1 禁止的旧一级分层

禁止使用 **`interfaces`、`infrastructure`、`application`、`domain`、`po`** 等业务或 DDD 风格一级包。

### 2.2 禁止的「深层业务树」示例

除非经架构评审并形成书面例外说明，禁止：

- ❌ **`auth/admin`**、**`auth/site`**、**`auth/shared`**
- ❌ **`admin/auth/session`** 等深层业务树
  
**Spring Security 认证链路（过滤器、未登录 / 无权限入口）：** **`admin`** 等业务模块中使用 **`security/`**（如 **`AuthContextSynchronizingFilter`**、**`AdminAuthenticationEntryPoint`**、**`AdminAccessDeniedHandler`**），并由 **`config.AdminSecurityConfig`** 编入 **`SecurityFilterChain`**；**`handler/`** 仅承载 **全局异常**（如 **`GlobalExceptionHandler`**），与 Security 专有组件区分开。

骨架类模块（**`site-car` / `site-cake` / `config`** 子域等）在多级分包上允许 **占位式**结构，但一旦进入真实业务迭代，应逐步 **向上述一级职责目录收口**。

## 3. 父目录 → 类名后缀

> **完整条文**（错放目录、模糊命名、功能归纳）：总纲 **[§3 文件名与文件夹职责匹配规则](./单模块文件结构与AI开发约束规则V1.md#3-文件名与文件夹职责匹配规则)**。下表为速查。

| 目录 | 后缀 | 示例 |
|------|------|------|
| `config` | `XxxConfig` | `AdminSecurityConfig` |
| `controller` | `XxxController` | `AdminAuthController` |
| `service` | `XxxService` | **接口**占位：`AdminAuthService`、`AdminRefreshCookieService`、`AdminRefreshSessionService`；**实现类**统一在 **`service.impl`**，后缀 **`XxxServiceImpl`**（见 §6） |
| `mapper` | `XxxMapper` | `AdminUserMapper` |
| `entity` | `XxxEntity` | `AdminUserEntity` |
| `handler` | `XxxHandler` | **`GlobalExceptionHandler`**（REST 全域异常）；**不要**再放 Spring Security 的 **`AuthenticationEntryPoint` / `AccessDeniedHandler`**——见 **`security`** 行 |
| `security` | 按 Spring 接口或约定名 | `AuthContextSynchronizingFilter`、`AdminAuthenticationEntryPoint`、`AdminAccessDeniedHandler` |
| `exception` | `XxxException` | （业务例外：多数用 `common.BusinessException`） |
| `utils` | `XxxUtils` | **仅限**静态、无 `@Component` / 无配置注入的工具 |
| `properties` | `XxxProperties` | **`AuthJwtProperties`**（`auth`：`security.jwt.*`）、`AdminAuthProperties`、`AuthJwtKeyProperties` |
| `constant` | `XxxConstants` | `JwtClaimConstants` |
| `filter` | `XxxFilter` | 仅限 **通用 Web 过滤器**；**Admin JWT 上下文同步过滤器**归宿见 **`security.AuthContextSynchronizingFilter`** |
| `interceptor` | `XxxInterceptor` | — |

**说明：** Spring Security 中 **`AuthenticationEntryPoint`** /**`AccessDeniedHandler`** 的官方类型名不包含 `Json`。**推荐**与本项目 JSON 语义一致的 **`AdminAuthenticationEntryPoint` / `AdminAccessDeniedHandler`**，并与 **`security/`** 同包归档，避免与 **`handler.GlobalExceptionHandler`** 混放。

## 4. `dto` 目录规范（压平：`com.example.module.dto`）

业务模块 **`dto`** **不再**拆分 **`request` / `response` / internal** 子包；所有 DTO **直接放在**模块根 **`dto`** 包下 **（一级压平）**，用 **后缀**区分用途。

### 4.1 命名（统一以 `Dto` 结尾）

| 用途 | 命名 |
|------|------|
| HTTP 接口请求体 | **`XxxRequestDto`** |
| HTTP 接口响应体（或可序列化快照） | **`XxxResponseDto`** |
| 响应内部嵌套结构（或认证流程内部传递的非 HTTP Body 顶层类型） | **`XxxDto`** |

### 4.2 禁止扩散

- **`dto/`** 下禁止再使用 **`XxxRequest`（无 `Dto`）**、**`XxxResponse`（无 `Dto`）**、**`XxxOutcome` / `XxxSummary` / `XxxPayload`** 等与上述口径并行的多套后缀。
- **Sealed interface** 等在认证内部传递的类型（例如 **`RotateRefreshDto`**）：仍放在 **`dto`** 根包，后缀 **`Dto`**。

---

## 5. `utils` 规范

允许写入 **`utils`** 的类必须同时满足：

- **纯静态**方法为主（或仅存 **无状态的 `final`** 私有构造工具类）
- **不是** Spring **`@Bean`/`@Component`**
- **不显式注入** **`@Autowired`/`Environment`/`*Properties***

若逻辑依赖 **`AdminAuthProperties` / `AuthJwtProperties`** 或其它配置：**不得**起名 **`XxxUtils`**，应归为 **`service.XxxService`**（或极小范围的 **`properties` 绑定类 + `@Service`** 编排）。

---

## 6. `service` / `service.impl` 规范（本项目定案）

- **`service/`**：**只放接口**（**`public interface XxxService`**）。**不写** **`@Service`**、**不写**默认方法承载业务流程（避免伪接口）。
- **`service.impl/`**：**只放实现类**，类名 **必须** 为 **`XxxServiceImpl`**，并 **`@Service`/`@Component`** 等按需标注；**多套生产实现**（如 **`RedisAdminRefreshSessionServiceImpl`**）也通过条件装配挂载到同一 **`XxxService` 接口**下。
- **调用方**：**`Controller`** 与其它 **`Service`** **必须依赖接口**，**禁止**字段类型写死 **`XxxServiceImpl`**。
- **测试替身**：`test` profile 或 `src/test/java` 中为 Redis 等提供替身；**生产 `main` 路径**不得在 4F 规范外随意混入 **`InMemory*Impl`**（除非与约定的 **`test` profile** 支撑本地运行的设计一致）。

---

## 7. `auth` 模块（单一可执行服务，4F）

`auth` **不是**仅供其它模块引用的「纯 jar 库」，而是 **独立启动的认证服务**，同时内部仍采用企业型一级分包（与 `admin` / `site-app` **同构习惯**）：

- **`controller`**：**`/api/auth/admin/login`**、**`/api/auth/admin/refresh`**、**`/api/auth/admin/logout`**、`GET /api/auth/ping` 等  
- **`service` / `service.impl`**：登录编排、JWT 签发、Refresh 轮换、会话吊销等  
- **`dto` / `entity` / `mapper`**：**`entity`** 仅 **表映射**（与持久化一一对应）；**`dto`** 含 **HTTP 契约** 与 **服务内部传递**（含 JWT 签发/解析用 **`XxxDto`**，如 **`IssuedAccessTokenDto`**）。**`mapper`**：**`admin_user`** 等只读表（**自持 Mapper**，**不得**依赖 **`admin` 模块 jar**）  
- **`config`**：Security、OpenAPI、JWT、Redis 会话等 **`XxxConfig`**  
- **`security` / `filter`（若有）** 等与 Spring Security 协作组件  

**`admin` 业务模块** **禁止** Maven 依赖 **`auth` 实现包**；跨服务只靠 **`common.security`** 与 **HTTP/API 契约** 对齐。

严禁在 **`com.mywebsite.auth`** 下再划 **`auth.admin` / `auth.site`/** 等 **第二套业务域分包**（Maven 模块已表达边界）。

### 7.1 `admin` 模块（Spring 按层 + Resource Server）

与 **Spring Boot 常见分层**一致；**认证 HTTP 已迁 `auth`**，本模块聚焦 **后台业务 API + OAuth2 Resource Server 验签**：

- **`config`**：安全配置、OpenAPI、**`AdminJwtDecoderConfig`**（`jwk-set-uri` + `iss`/`aud` 校验）等，类名 **`XxxConfig`**。  
- **`security`**：`AuthenticationEntryPoint`、`AccessDeniedHandler`、**`AuthContextSynchronizingFilter`** 等；**勿**放入 **`handler/`**（后者仅 **`GlobalExceptionHandler`** 类 REST 异常）。  
- **`controller` / `service` / `service.impl` / `dto` / `entity` / `mapper`**：业务与持久化；**`dto`** 一律 **`XxxRequestDto`/`XxxResponseDto`/`XxxDto`**，**勿**在 **`service`** 下塞 DTO 类型。

### 7.2 Admin RBAC 与分层包（5D.1 收敛后）

**`com.mywebsite.admin.rbac` 已删除**。RBAC 相关类与 Admin 其它业务 **同一套按层分包**；功能由 **类名** 表达（`AdminRoleController`、`AdminRbacQueryMapper` 等），**不再** 使用 `rbac/controller`、`rbac/dto`、`rbac/support` 等功能域子树。

```text
com.mywebsite.admin
├── controller          # AdminRoleController、AdminPermissionController、AdminUserRoleController …
├── dto                 # AdminRbacDtos（仅 HTTP 契约）；AdminAuthMeDto 等
├── mapper              # AdminRbacQueryMapper、AdminRoleManagementMapper …
├── service / service.impl   # 含 AdminRoleGuard、AdminAuthMeService
├── security            # AdminPermissionChecker、CurrentAdminAuthorizationHolder、AdminCurrentAuthorizationSnapshot
└── constant            # AdminRbacConstants、AdminRbacMessageKeys
```

- **禁止** 在 `admin` 下恢复 **`rbac/`** 功能域包或 **`support/`** 垃圾桶目录。
- **测试 SQL**：`admin/src/test/resources/rbac/*.sql` 路径 **保留**（与 Java package 无关）。

详见 **[阶段5D.1 综合审查收敛](../../作業検査/阶段5D.1-Admin模块包结构命名与RBAC链路综合审查收敛.md)**（及 [包迁移短文](../../作業検査/阶段5D.1-Admin-RBAC包结构收敛.md)）。

## 8. 新增文件四问（强制）

每次 **新增 / 移动 / 重命名 Java 类** 前必须回答（详见总纲 **§11**）：

1. 为什么不能放在现有 **ServiceImpl**？  
2. 是否真的被 **两个以上** 类稳定复用？  
3. 是否会造成 **跨模块** Maven / import 依赖？  
4. 是否符合 **当前 Maven 模块职责**？  
5. **文件名后缀是否与所在目录匹配**（总纲 **§3.1**）？

**答不清 → 不允许新增、移动或重命名文件。**

### 8.1 Cursor / Copilot 快速检查（命名与分包）

1. **目录 + 后缀**：`controller/*Controller`、`service/*Service`、`service/impl/*ServiceImpl`、`mapper/*Mapper`、`entity/*Entity`、`dto/*Dto`、`config/*Config`（总纲 §3）。  
2. REST 契约 → **`dto`** 根包，不放 **`common`**。  
3. 业务流程 → **`service` + `service.impl`**；**禁止** `ServiceImpl` 放在 `service` 根目录。  
4. **`auth`** 出现 RBAC/菜单类 → **立即回迁** **`admin`**。  
5. 禁止默认 **Support / Helper / Manager / Processor** 等模糊命名（总纲 §3.3、§10）。
