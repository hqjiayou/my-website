## 4. 模块职责

- `gateway`
  - 统一 API 网关，端口 **`8080`**（默认）。
  - **路由（当前事实）**：**`/api/auth/**`** → **`http://localhost:8083`（`auth`）**；**`/api/admin/**`** → **`http://localhost:8081`（`admin`，业务 API，含 `/api/admin/auth/me`）**；**`/api/site/**`** → **`http://localhost:8082`（`site-app`，含 `/api/site/auth/me`）**。**`/api/auth/**` 须在 **`/api/admin/**`、`/api/site/**`** 之前声明。
  - **不**承载业务逻辑；**不**直连 PostgreSQL / Redis / MinIO；**不**在网关实现与业务服务重复的 JWT 授权逻辑（由各应用 **OAuth2 Resource Server** 处理）。
- `auth`
  - **单一、可执行的 Spring Boot 服务**（**不再有 `auth-core` / `auth-app` 拆分**），默认端口 **`8083`**（`AUTH_APP_PORT`）。
  - **职责**：Admin（与未来 Site）**认证主链路**——**Login / Refresh / Logout**，Access JWT **RS256 签发**、**`GET /.well-known/jwks.json`**、HttpOnly Refresh Cookie、**Redis** 刷新会话（Rotation / Replay 防御）；OpenAPI、`i18n/auth` 承载 **`admin.auth.*`** 等认证错误语义。
  - **Flyway**：在 Auth **关闭**；与 Admin **共用库**时由 **`admin` 执行 migration**，Auth **仅读** `admin_user` 等表（自持 Mapper，**不**依赖 `admin` jar）。
  - **落地**：**[阶段4F](../认证与安全/阶段4F-Auth单服务收敛与认证主链路上提落地说明.md)**、**[阶段4G](../认证与安全/阶段4G-RS256与JWKS签名验签体系迁移说明.md)**；架构脉络：**[阶段4D](../认证与安全/阶段4D-Auth独立认证服务架构回归设计与迁移方案.md)**。
- `admin`
  - 后台管理后端应用，端口 **`8081`**。
  - **OAuth2 Resource Server**：校验 **Access JWT**（**`iss` / `aud` / `subject_type`** 等与受众一致）；**不**实现 **`/api/auth/*`** 认证编排（由 **`auth`** 提供）。**`/api/admin/auth/me`** 为业务上下文接口。
  - **RBAC 管理接口**（角色/权限/用户-角色等，**5B～5D**）与 **Resource Server** 验签；**菜单树与 `/auth/me.menus`（5E）待开始**。
- `site`
  - Maven 聚合模块，不直接启动。
- `site/site-app`
  - 前台站点后端启动模块，端口 **`8082`**。
  - 依赖 `site-core` / `site-car` / `site-cake`；**未来**面向 **多门户、多行业站点**，本阶段保留扩展点，不强制拆分进程。
- `site/site-core`
  - 前台站点公共核心能力（`SiteContext`、站点用户与配置等）。
- `site/site-car` / `site/site-cake`
  - 行业业务模块骨架。
- `infra`
  - PostgreSQL、Redis、MinIO/S3、MyBatis-Plus、Flyway 机制、**系统消息 i18n** 等。
- `common`
  - `ApiResponse`、`ErrorCode`、`BusinessException`、`PageResult`；**`com.mywebsite.common.security`**（**`SubjectType`**、**`SubjectCodes`**、JWT 声明常量、`TokenAudience`、`AuthenticatedUser`、`AuthContext` 等**轻量契约**）。
- `agent`
  - 对接外部 **AI/Agent** 服务的客户端层。

### 4.1 系统消息国际化（阶段 4B.5）

- **定案**：[后端多语言支持策略设计 V1](../认证与安全/后端多语言支持策略设计V1.md)。
- **Locale**：仅用 **`Accept-Language`**（BCP 47）；缺省 **`ja-JP`**；首批 **`ja-JP` / `zh-CN` / `en-US`**（`app.i18n`）。
- **资源**：各应用 **`spring.messages.basename`** 拼接 **`i18n/common`** 与模块内 **`i18n/admin` / `i18n/auth` / `i18n/site`**（以实际模块为准）；**Login/Refresh/Logout 等认证错误消息归 `auth` bundle**。

- **库模块**：`common`、`infra`、`agent`、`site-core`、`site-car`、`site-cake` 等。

## 6. 认证与用户模型边界

> **实现现状（4F + 4G）**：**认证主进程为 `auth`**（**RS256** 签发 Access JWT、**JWKS** 发布公钥、管理 Refresh **Redis** 会话与 Cookie）。**`admin` / `site-app`** 为 **OAuth2 Resource Server**，**仅验签**与授权，**不实现** Login/Refresh/Logout 编排。

**`auth` 服务**可：

- 按 **`/api/auth/*`** HTTP 承载 **Login / Refresh / Logout**（及 **`GET /api/auth/ping`**）与 **RS256** Access JWT **签发**；公钥经 **JWKS** 发布（**`/.well-known/jwks.json`**）。载荷 **`subject_type`** 使用 **`SubjectType`**，解析时 **枚举比对**，与 **`aud`（面向谁）** 解耦。
- 使用 **`com.mywebsite.common.security`** 中 **Claims / Audience / `AuthenticatedUser`** 等契约，与同仓库 **Resource Server** 对齐。

**`auth` 不应**将 **`admin`/`site`/`admin` 业务包**作为 Maven 依赖；读库表使用 **本模块自持** `entity`/`mapper`。

**补充（阶段 4D / 4F）**：登录验证可读 **`admin_user`**（及未来 **`site_user`**）——表在共享库中，**Auth 自持 Mapper**，**禁止** Maven 依赖 **`admin` jar**。详见 **[阶段4D](../认证与安全/阶段4D-Auth独立认证服务架构回归设计与迁移方案.md)**；落地见 **[阶段4F](../认证与安全/阶段4F-Auth单服务收敛与认证主链路上提落地说明.md)**。

**admin** 侧用户/权限表归属（业务域）：

- `admin_user`、`admin_role`、`admin_permission`、`admin_user_role`、`admin_role_permission`

**site-core** 侧用户归属：

- `site_user`、`site_user_profile`；可扩展 `site_user_auth`

前台统一 **`site_user`** + **`site_id` / `site_code`** 多站点隔离；不为 car/cake 各建独立用户根表。

**下一阶段**：**5A**（RBAC 深化）。**Gateway 4H / 迁移 4I**：已完成（**4H**见 **[联调说明/阶段4H](../../联调说明/阶段4H-Gateway唯一入口全链路真实联调.md)**；**4I**见 **[阶段4I](../../联调说明/阶段4I-迁移清理收口.md)**）。

## 7. 持久层与迁移规范

默认持久层采用 MyBatis-Plus，不引入 JPA / Hibernate。

约定：

- Mapper 位于各业务模块 **`mapper`** 包下，并使用 `@Mapper` 标注。
- 复杂查询可以使用自定义 Mapper 与 XML SQL。
- XML Mapper 默认扫描 `classpath*:/mapper/**/*.xml`。
- 本阶段只完成持久层框架接入说明；业务表已通过 Flyway V1 migration 落地 DDL（详见仓库内 migration 与设计文档）。

Flyway 是唯一数据库结构迁移机制。

约定：

- **脚本目录（唯一来源）**：`services/website-services/infra/src/main/resources/db/migration`
- **`site-app` 默认不运行 Flyway**（避免与 `admin` 共用同一库时 migration 重复执行）；说明见 `site/site-app/src/main/resources/db/README.md`
- migration 命名：`V{version}__{description}.sql`
- 任何表结构变更必须通过 migration 文件提交
- 首批表结构参见：[数据库模型设计 V1](../数据与持久层/数据库模型设计V1.md) §8、`V1__init_platform_core_tables.sql`；**已落地表的字段 / 约束 / 索引** 以 `docs/数据字典/` 为准。
- **Java 持久层（Entity / Mapper / MyBatis-Plus 约定）**：[`Java持久层设计V1.md`](../数据与持久层/Java持久层设计V1.md)（阶段 3A/3B 已定稿；数据库映射类统一 **`XxxEntity`**，见该文档 §3）。

## 8. 模块内 Java 包结构（Spring Boot 常规）

主要业务边界已由 **Maven 多模块**划分；**模块内部**不再使用 `interfaces` / `application` / `domain` / `infrastructure` 作为一级分层包名，统一为按职责命名的常规包，例如：

```text
config/
controller/
handler/
mapper/
entity/
service/
dto/
exception/
utils/
security/
filter/
interceptor/
properties/
constant/
context/
token/
client/
```

约束：

- **Controller** 放在 **`controller`**。
- **全局异常处理器**（如 **`GlobalExceptionHandler`**）放在 **`handler`**；**Spring Security 认证 / 鉴权组件**（如 **`AuthenticationEntryPoint`、`AccessDeniedHandler`、JWT 上下文同步 **`Filter`**）放在 **`security`**，并由 **`AdminSecurityConfig`** 等编入 **`SecurityFilterChain`**。**业务异常类型**（如 **`BusinessException`**）放在 **`exception`**（或 **`common`** 等共享模块，按现有约定）。
- **持久化**：**`entity`**（表映射 **`XxxEntity`**）、**`mapper`**；MyBatis-Plus 全局插件、审计填充等由 **`infra`** 模块提供（**`infra.config`** / **`infra.handler`** 等）。
- **配置类** 类名统一 **`XxxConfig`**（如 **`AdminOpenApiConfig`**），替代 **`XxxConfiguration`**（框架 **`XxxAutoConfiguration`** 除外）。
- **不**为凑齐层次而新建空目录；无业务代码的模块保持精简。
- **禁止**仅为「模块看上去完整」而新增 **空 `*ModuleMarker`** 占位类；Bean 装载依赖 **`@Component` / `@Configuration`** 与 **`scanBasePackages`** 即可。

**更细的 DTO/common/utils/service 约束**（Cursor / Codex **生成代码前应遵守**）见：[后端包结构与命名规范 V1](./后端包结构与命名规范V1.md)。

## 9. 本地基础设施

本地开发依赖 **PostgreSQL**、**Redis**；对象存储 **MinIO / AIStor** 由既有 **local-stack**（或其它等价实例）提供。

### 9.1 local-stack（唯一基础设施栈）

**本地基础设施统一使用既有 local-stack**（典型映射：**`local-postgres` → `localhost:5432`**，**`local-redis` → `localhost:6379`**，**`local-aistor` → `localhost:9000`**）。**本仓库不在 `services/website-services` 内附带 PostgreSQL / Redis / MinIO 的 Compose**，以避免第二套实例与 JDBC / seed 错位。**阶段 4B Admin 认证**主线仍为 **PostgreSQL + Redis**。

### 9.2 默认端口与配置占位

本地常见端口：

- PostgreSQL：`localhost:5432`
- Redis：`localhost:6379`
- MinIO / AIStor API：`http://localhost:9000`（由 **local-stack** 暴露）
- MinIO / AIStor Console：以栈配置为准（常见 `9001`）

`admin` 与 `site-app` 通过 `application-local.yml` 接入本地基础设施：**YAML 仅占位 `${...}`**，连接串、账号与 MinIO 键值在 **`services/website-services/.env`**（范本 **`.env.example`**）中声明。**应用 `.env` 与 local-stack 目录下的 `.env` 分开维护**。

敏感信息通过环境变量（或 `.env` 加载到系统属性）注入，不在仓库中写入生产凭据。

## 10. 运行与验证

构建：

```bash
mvn clean install -DskipTests
```

启动（建议在 `services/website-services` 目录；**Auth 需 `-am` 带上 common/infra**）：

```bash
mvn -pl gateway spring-boot:run
mvn -pl auth -am spring-boot:run
mvn -pl admin -am spring-boot:run
mvn -pl site/site-app -am spring-boot:run
```

验证：

- `GET http://localhost:8080/api/admin/ping`（经 Gateway，需 Bearer）
- `GET http://localhost:8080/api/site/ping`
- `GET http://localhost:8080/api/auth/ping`（Gateway → Auth）
- `GET http://localhost:8081/api/admin/ping`（直连 Admin，需 Bearer）
- `GET http://localhost:8082/api/site/ping`
- `GET http://localhost:8083/api/auth/ping`（直连 Auth）
- **各服务** `/actuator/health`
- Swagger：`admin` 8081、`auth` 8083、`site-app` 8082；**`gateway` 无 springdoc-openapi**

测试：

```bash
mvn test
```

持久层真实 PostgreSQL 回归（专用验证库、`verify-pg`、Maven Profile **`persistence-verify-pg`**）：

```bash
cd services/website-services
mvn clean test -Ppersistence-verify-pg -pl admin,site/site-app -am
```

详见：[持久层真实 PostgreSQL 验证说明](../../数据文档/持久层真实PostgreSQL验证说明.md)。
