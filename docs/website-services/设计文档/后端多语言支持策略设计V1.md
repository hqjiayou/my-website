# 后端多语言支持策略设计 V1（阶段 4B.5）

## 文档元信息与边界

| 项 | 说明 |
| --- | --- |
| 性质 | **设计定案**：系统错误与校验类「对外可读 message」在多模块后端中的加载、Locale 选择与回退规则 |
| 阶段 | **阶段 4B.5** 落地；为 **阶段 4C（Admin 认证真实联调）** 提供稳定错误文案基线 |
| 非目标 | **业务数据多语言**（站点名称、页面内容、商品名等）不在本文与 4B.5 范围；**前端 i18n**、**Swagger 文案多语言** 不在范围 |

---

## 1. 设计目标

1. **统一语言标识**：全后端仅使用 **BCP 47** 语言标签（如 `ja-JP`、`zh-CN`、`en-US`）。禁止自定义 `jp`/`cn` 短码、禁止用枚举硬编码「语言种类」、禁止在数据库用 `title_ja/title_zh/title_en` 三列表达业务多语言（见 §12）。
2. **系统消息可维护**：错误码、校验失败、认证失败等 **message 以稳定 `messageKey` 驱动**，翻译集中在各模块 `messages*.properties`。
3. **默认回退日文**：`messages.properties` 作为 **日文根资源**；请求语言缺省、不支持或某 key 在目标语言包中缺失时，按约定回退到日文；日文仍缺失时返回 key 并打 **warn** 日志（见 §3）。
4. **多模块清晰拆分**：可复用能力上提至 `common` / `infra` / `auth`；Admin 专属文案留在 `admin`，避免 common 变成业务文案堆场。

---

## 2. 当前落地范围（4B.5）与留白

**已落地**

- **API 业务异常**：`BusinessException` 携带 `messageKey` + `messageArgs`；`GlobalExceptionHandler` 用 `LocalizedMessageService` 解析后写入 `ApiResponse.message`（`code`/`data` 不变）。
- **参数校验**：Bean Validation 的 `message = "{...}"` 由 Spring `MessageSource` 按请求 Locale 解析；Admin 登录 DTO 已覆盖用户名/密码必填、长度上限等关键项。
- **Admin 认证主路径错误**：登录失败、账号不可用、刷新无效等与认证相关的对外 message 已 key 化。
- **Spring Security**：`AuthenticationEntryPoint` / `AccessDeniedHandler` 返回的 JSON **仅 message 本地化**（401/403 HTTP 语义不变）。
- **`ApiResponse.success()`**：`message` 字段可为 `common.result.success` 等 key，由 **`ApiResponseMessageLocalizationAdvice`** 在写出前本地化（仍为 `ApiResponse`，结构不变）。
- **`site-app`**：对齐 `GlobalExceptionHandler` + `spring.messages.basename`（至少 common+auth）+ `app.i18n`，为后续前台错误口径预留与其它应用一致的处理方式。

**刻意不做（留白）**

- **数据库 Flyway / 语言表**：不新增迁移、不建模 `locale` 内容表。
- **RBAC、Site 登录、网关层统一错误体**：不按 4B.5 扩张；网关与 Resource Server **`invalid_token` + WWW-Authenticate** 等与阶段 4A/4B 文档一致的边界保持不变。
- **Swagger / OpenAPI 描述多语言**：不在本轮处理。

## 3. 语言标识与回退策略

### 3.1 首批支持语言

配置项（应用 `application.yml`）：

```yaml
app:
  i18n:
    default-locale: ja-JP
    supported-locales:
      - ja-JP
      - zh-CN
      - en-US
```

首轮实现：`I18nProperties` 在校验启动配置时校验标签基本合法（`_` 会规范为 `-` 再解析）。

### 3.2 Locale 来源

- **仅此一种**：HTTP 请求头 **`Accept-Language`**。
- **不使用**：Cookie Locale、Session Locale、URL path Locale（后续若接入需新开设计）。

### 3.3 `LocaleResolver`

- **`AcceptHeaderLocaleResolver`**：`supportedLocales` 与 **default locale = `ja-JP`** 由 `app.i18n` 绑定；与 Spring Security、MockMvc、`LocaleContextHolder` 行为一致。
- **`Accept-Language` 缺失** 或不支持的语言（示例：`ko-KR`）：解析结果为 **配置的 default locale（`ja-JP`）**。

### 3.4 Message 解析与回退链路

资源文件命名（见 §4）：

| 优先级（概念上） | 文件 | 语义 |
| --- | --- | --- |
| 根默认（日文） | `messages.properties` | **日文**基准与最终回退市 |
| zh-CN | `messages_zh_CN.properties` | 简体中文补丁 |
| en-US | `messages_en_US.properties` | 美式英文补丁 |

规则：

1. 能匹配 **`Accept-Language` + supportedLocales`** → 使用该 **`Locale`** 解析。
2. 目标语言 properties **缺少某 key** → 依赖 Spring `MessageSource` 与 bundle 链 **回退到 `messages.properties`（日文）**。
3. **日文根仍无该 key** → `LocalizedMessageService` **返回 `messageKey` 原文**，并记录 **warn**（不在业务模块重复实现该逻辑）。

## 4. 多模块资源文件组织

### 4.1 路径约定

按模块classpath 根下放：

```text
common/src/main/resources/i18n/common/messages.properties
common/src/main/resources/i18n/common/messages_zh_CN.properties
common/src/main/resources/i18n/common/messages_en_US.properties

auth/src/main/resources/i18n/auth/messages.properties   # 亦为日文根
auth/src/main/resources/i18n/auth/messages_zh_CN.properties
auth/src/main/resources/i18n/auth/messages_en_US.properties

admin/src/main/resources/i18n/admin/messages.properties
admin/src/main/resources/i18n/admin/messages_zh_CN.properties
admin/src/main/resources/i18n/admin/messages_en_US.properties
```

**不默认增加** `messages_ja_JP.properties`：除非日后存在「日文地区变体」的真实需求。

### 4.2 应用侧 `basename`

- **Admin**（示例）：
  ```yaml
  spring:
    messages:
      basename: i18n/common/messages,i18n/auth/messages,i18n/admin/messages
      encoding: UTF-8
      fallback-to-system-locale: false
  ```
- **Site-app**（当前无 site 专有文案时仍可预留）：
  ```yaml
  spring:
    messages:
      basename: i18n/common/messages,i18n/auth/messages
  ```

加载顺序中包含多个 basename 时：**靠后的 basename 中同 key 可覆盖靠前的**（仅当真有 key 冲突时需要约定优先级；正常情况下按模块前缀区分 key，避免冲突）。

### 4.3 `messageKey` 命名

格式：**`<module>.<domain>.<action>.<reason>`**（全小写、点分层；稳定、无语种后缀）。

示例：

- `common.error.bad-request`
- `auth.unauthorized`、`auth.access.denied`
- `admin.auth.login.failed`、`admin.auth.password.too-long`

## 5. 基础设施与分层（实现要点）

| 层次 | 职责 |
| --- | --- |
| **`common`** | `ErrorCode`：`code` + **`messageKey`**；`BusinessException`：`messageKey` + `messageArgs`；**不**依赖 Spring / infra |
| **`infra`** | `I18nProperties`、`I18nConfig`（`LocaleResolver`）、`LocalizedMessageService` / `Impl`；`ApiResponseMessageLocalizationAdvice`（仅当 `message` 形似 key 时再解析，避免自然语言二次替换） |
| **`auth` / `admin` / 未来 site 子模块** | 仅维护本域 `i18n/<module>/messages*.properties` |

**`LocalizedMessageService` 接口（摘要）**

- `getMessage(String messageKey, Object... args)`：优先当前请求上下文的 Locale；无请求时用 **`ja-JP`**。
- `getMessage(String messageKey, Locale locale, Object... args)`：显式 Locale。
- `getMessage(HttpServletRequest request, String messageKey, Object... args)`：供 Security 过滤器链等使用。

---

## 6. 异常与校验的国际化约定

- **Handler 层**：将 `BusinessException.getMessageKey()` + `getMessageArgs()` 交给 `LocalizedMessageService`，结果写入 `ApiResponse.message`。
- **校验**：DTO 上使用 `message = "{key}"`；`MethodArgumentNotValidException` 取 **首条** `FieldError.getDefaultMessage()`（已由 Spring 按 Locale 解析）。
- **Security 401/403**：`AdminAuthenticationEntryPoint` / `AdminAccessDeniedHandler` 使用 **`auth.unauthorized`** / **`auth.access.denied`**（或后续更细 key，仍归 `auth` 模块资源）。

### 6.1 Resource Server 与自定义 EntryPoint 的边界

- **未携带或非法 Bearer** 等走 **`AdminAuthenticationEntryPoint`** 的路径：返回 **统一 JSON `ApiResponse`**，`message` 已本地化。
- **JWT 验证失败等 RFC 6750 场景**（如响应头含 `invalid_token`）：保持 **阶段 4A/4B 已定边界**，本轮 **不强制** 改成与业务 JSON 完全一致；若将来要统一，在 **阶段 4C+** 单独立项。

---

## 7. 新增语言的标准流程（配置驱动）

不涉及业务 Java 重构，仅：

1. 在 `app.i18n.supported-locales` 增加新的 BCP 47 标签（如 `ko-KR`）。
2. 在各相关模块 **`i18n/<module>/` 下增加** `messages_<lang>_<REGION>.properties`（文件名与 **`Locale`** 约定一致）。
3. 为新语言翻译已有 **messageKey**（可先拷贝日文根再翻）。
4. 回归：**`Accept-Language`** 为该语言时能命中；不支持语言仍回 **`ja-JP`**。

---

## 8. 测试基线（4B.5）

- **Locale**：无头 / `ja-JP` / `zh-CN` / `en-US` / 不支持语言 → 日文默认。
- **Message**：命中目标语言；目标语言缺 key → 日文回退；全局缺 key → 返回 key + warn。
- **业务异常**：同 `code`、不同 Locale 下 `message` 不同。
- **校验**：Admin Login DTO 多场景在多语言头下断言 `message`。
- **Security Handler**：401/403 JSON `message` 随 `Accept-Language` 变化（单测或直接测 Handler）。

---

## 12. 未来「业务数据多语言」边界（非 4B.5）

### 12.1 当前不做数据库多语言内容表

阶段 4B.5 **仅** 系统消息（错误、校验、安全提示等）国际化。

### 12.2 未来原则

以下内容未来需要多语言时，**禁止**：

- `title_ja`、`title_zh`、`title_en` 等 **固定语种列扩展**；

应采用 **`locale` 维度**（独立翻译表、`locale-keyed JSON` 等），在 **站点内容系统设计** 阶段单独定案；与本文 **系统 message i18n** 解耦。
