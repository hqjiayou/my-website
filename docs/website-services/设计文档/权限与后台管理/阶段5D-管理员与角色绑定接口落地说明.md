## 3. 接口契约

### 3.1 GET `/api/admin/users/{id}/roles`

响应 `data` 示例：

```json
{
  "userId": 100,
  "userCode": "ADMIN_000100",
  "username": "editor_user",
  "roles": [
    {
      "roleId": 1,
      "roleCode": "editor",
      "roleName": "Editor",
      "status": "ACTIVE",
      "protectedRole": false
    }
  ]
}
```

- `userCode`：`SubjectCodes.formatAdminSubject`（如 `ADMIN_000100`）
- `protectedRole`：`true` 表示 `super_admin` 角色（只读标识，查询仍允许）

### 3.2 PUT `/api/admin/users/{id}/roles`

请求体：

```json
{ "roleCodes": ["admin"] }
```

响应体与 GET 相同结构（更新后快照）。

## 4. 业务规则

| 规则 | 行为 |
|------|------|
| 目标用户存在 | 否则 `404` + `admin.rbac.user.not-found` |
| `roleCodes` 非空 | 否则 `400` + `admin.rbac.user-role.empty` |
| 角色存在且 `ACTIVE`、未删除 | 否则 `400` + `admin.rbac.role.not-found` |
| 禁止修改自己 | `targetUserId == currentUserId` → `admin.rbac.user-role.self-update-denied` |
| 禁止绑定 `super_admin` | 请求含 `super_admin` → `admin.rbac.role.code.reserved` |
| 禁止修改 `super_admin` 用户 | 目标用户已是 super_admin → `admin.rbac.super-admin.protected` |
| 替换式更新 | 事务内软删旧 `admin_user_role`，插入新绑定 |

当前用户 ID：从 `AuthContext` + JWT `sub` 解析（与 `/auth/me` 一致）。

---

## 5. super_admin 保护策略（保守）

- **不允许**通过本接口授予或移除 `super_admin`
- **不允许**修改已拥有 `super_admin` 的用户的角色绑定
- 运行时鉴权仍由 `AdminPermissionChecker` 对 `super_admin` **短路**

---

## 6. 代码结构

| 类型 | 路径 |
|------|------|
| Controller | `admin/.../controller/AdminUserRoleController.java` |
| Service | `AdminUserRoleManagementService` / `Impl` |
| Mapper | `AdminUserRoleManagementMapper` |
| DTO | `dto/AdminRbacDtos`：`AdminUserRoleResponse`、`AdminUserRoleUpdateRequest`、`AdminRoleBindingDto` |
| i18n | `admin.rbac.user.*`、`admin.rbac.user-role.*`、`admin.rbac.super-admin.protected` |

**分层**：Controller / Checker 不直连 Mapper；无新增 Repository / Facade。

---

## 7. Method Security

```java
@PreAuthorize("@adminPermissionChecker.hasPermission('admin:user:role:view')")
@PreAuthorize("@adminPermissionChecker.hasPermission('admin:user:role:update')")
```

`AdminSecurityConfig` **仅** `authenticated`，无 URL 权限映射。

---

## 8. 缓存预留（未实现）

后续若引入 Redis 权限缓存，建议键：

`rbac:admin:user:{userId}:permissions`

`PUT /api/admin/users/{id}/roles` 成功后须失效**目标用户**缓存。本阶段无缓存，无需清理。

---

## 9. `/auth/me` 回归

- 更新用户角色后，**同一 JWT** 再次请求 `/api/admin/auth/me` 可见新 `roles` / `permissions`
- `permissions` **不**来自 JWT；`menus` 仍为 `[]`（5B 约定）

测试：`AdminUserRoleManagementMvcTest#authMeReflectsUpdatedRolesWithoutNewJwt`
