# website-services 架构设计

本文档描述 `services/website-services` 当前 Java 后端多模块工程的架构分层、依赖约束与运行方式，作为后续业务迭代的基线文档。

- **设计与流程类正文**权威路径：**`docs/website-services/设计文档/`**（例如本文 **`架构设计.md`**、**`数据库模型设计V1.md`**、**`Java持久层设计V1.md`** 等）。
- **`docs/website-services/` 根目录**下若存在 **`架构设计.md`、`数据库模型设计V1.md`、`Java持久层设计V1.md`、`WSL与Docker环境配置说明.md`** 等 **同名入口**，**仅保留跳转说明**，**禁止**与 `设计文档/` 内正文并行维护两份完整文档。

## 1. 目标与范围

- 目标：保持结构清晰、可编译、可启动，并为 admin/site/gateway 后续扩展留出边界。
- 范围：统一网关、后台应用、前台站点聚合模块、公共认证抽象、基础设施接入。
- 非目标：当前不实现完整权限系统、登录注册、car/cake 业务功能、注册中心、消息队列或复杂网关鉴权。

## 2. 技术基线

- Java 21
- Maven 多模块
- Spring Boot 3.5.14
- Spring Cloud Gateway（gateway 模块）
- MyBatis-Plus（默认持久层框架，保留 XML SQL 能力）
- Flyway（数据库迁移）
- springdoc-openapi（admin/site-app API 文档）
- PostgreSQL（DataSource 自动配置）
- Redis（Spring Data Redis 自动配置）
- MinIO / S3 兼容对象存储（MinIO SDK）

## 4. 模块职责

- `gateway`
  - 统一 API 网关，端口 `8080`。
  - 路由 `/api/admin/**` 到 `http://localhost:8081`。
  - 路由 `/api/site/**` 到 `http://localhost:8082`。
  - 不承载业务逻辑，不直连 PostgreSQL/Redis/MinIO。
- `admin`
  - 后台管理后端应用，端口 `8081`。
  - 后续承载后台管理用户与权限模型。
- `site`
  - Maven 聚合模块，不直接启动。
- `site/site-app`
  - 前台站点后端启动模块，端口 `8082`。
  - 依赖 `site-core/site-car/site-cake` 并统一装配前台能力。
- `site/site-core`
  - 前台站点公共核心能力。
  - 承载 `SiteContext`、站点公共能力、站点配置读取能力、前台站点用户体系。
- `site/site-car`
  - 汽车站点业务模块骨架。
- `site/site-cake`
  - 蛋糕站点业务模块骨架。
- `auth`
  - 公共认证基础能力模块。
  - 只放 Token/JWT 抽象、认证上下文、当前登录用户抽象。
  - Token audience 区分 `ADMIN` / `SITE`。
- `infra`
  - PostgreSQL、Redis、MinIO/S3 兼容对象存储等基础设施接入层。
  - 承载 MyBatis-Plus、Flyway 等基础设施接入。
- `common`
  - 通用基础模型：`ApiResponse`、`ErrorCode`、`BusinessException`、`PageResult`。
- `agent`
  - 后续对接 AI/Agent 运行服务的客户端层。
  - 不直接依赖 PostgreSQL/Redis/MinIO，不做业务数据编排。
- `config`
  - 网站配置业务域预留（主题、布局、SEO、Brand 等）。

## 5. 依赖拓扑

```text
gateway       -> Spring Cloud Gateway only

common
  ↑
infra         -> common
auth          -> common
agent         -> common
config        -> common, infra

site-core     -> common, infra, auth, config
site-car      -> site-core
site-cake     -> site-core
site-app      -> common, infra, agent, auth, config, site-core, site-car, site-cake

admin         -> common, infra, agent, auth, config
```

约束说明：

- `gateway` 不依赖业务模块，不接入数据库、Redis 或对象存储。
- `agent` 不直接依赖 `infra`，不读取业务数据、不访问文件存储、不缓存 AI 会话；这些编排由 `admin` 或 `site-app` 承担。
- `site` 是聚合模块，不承载代码。
- 仅 `gateway`、`admin`、`site-app` 是可执行 Spring Boot 应用。
- `common/infra/agent/auth/config/site-core/site-car/site-cake` 为普通 jar 模块。

## 6. 认证与用户模型边界

`auth` 是公共认证基础能力模块，不是具体用户域模块。

`auth` 可负责：

- Token / JWT 公共能力
- Token audience：`ADMIN` / `SITE`
- 认证上下文
- 当前登录用户抽象
- 公共认证接口与能力封装

`auth` 不应定义：

- `admin_user`
- `site_user`
- `admin_role`
- 任何具体业务用户实体

admin 侧用户体系由 `admin` 模块承载：

- `admin_user`
- `admin_role`
- `admin_permission`
- `admin_user_role`
- `admin_role_permission`

site 侧用户体系由 `site-core` 承载：

- `site_user`
- `site_user_profile`
- 如需要再扩展 `site_user_auth`

前台用户统一使用 `site_user`，通过 `site_id` 或 `site_code` 做多站点隔离。car/cake 不分别建立 `car_user`、`cake_user`。

当前认证策略采用 JWT 作为主认证模型，Admin / Site 认证逻辑隔离。Redis 未来用于 refresh token、主动失效、登出等扩展能力。本阶段只保留认证骨架，不实现登录注册、权限系统或完整 JWT 签发流程。

## 7. 持久层与迁移规范

默认持久层采用 MyBatis-Plus，不引入 JPA / Hibernate。

约定：

- Mapper 位于各业务模块 **`mapper`** 包下，并使用 `@Mapper` 标注。
- 复杂查询可以使用自定义 Mapper 与 XML SQL。
- XML Mapper 默认扫描 `classpath*:/mapper/**/*.xml`。
- 本阶段只完成持久层框架接入说明；业务表已通过 Flyway V1 migration 落地 DDL（详见仓库内 migration 与设计文档）。

Flyway 是唯一数据库结构迁移机制。

约定：

- **脚本目录（唯一来源）**：`services/website-services/infra/src/main/resources/db/migration`
- **`site-app` 默认不运行 Flyway**（避免与 `admin` 共用同一库时 migration 重复执行）；说明见 `site/site-app/src/main/resources/db/README.md`
- migration 命名：`V{version}__{description}.sql`
- 任何表结构变更必须通过 migration 文件提交
- 首批表结构参见：[数据库模型设计 V1](./数据库模型设计V1.md) §8、`V1__init_platform_core_tables.sql`；**已落地表的字段 / 约束 / 索引** 以 `docs/数据字典/` 为准。
- **Java 持久层（Entity / Mapper / MyBatis-Plus 约定）**：[`Java持久层设计V1.md`](./Java持久层设计V1.md)（阶段 3A/3B 已定稿；数据库映射类统一 **`XxxEntity`**，见该文档 §3）。

## 8. 模块内 Java 包结构（Spring Boot 常规）

主要业务边界已由 **Maven 多模块**划分；**模块内部**不再使用 `interfaces` / `application` / `domain` / `infrastructure` 作为一级分层包名，统一为按职责命名的常规包，例如：

```text
config/
controller/
handler/
mapper/
entity/
service/
dto/
exception/
utils/
filter/
interceptor/
properties/
constant/
client/
```

约束：

- **Controller** 放在 **`controller`**。
- **全局异常处理器**（如 **`GlobalExceptionHandler`**）放在 **`handler`**；**业务异常类型**（如 **`BusinessException`**）放在 **`exception`**（或 **`common`** 等共享模块，按现有约定）。
- **持久化**：**`entity`**（表映射 **`XxxEntity`**）、**`mapper`**；MyBatis-Plus 全局插件、审计填充等由 **`infra`** 模块提供（**`infra.config`** / **`infra.handler`** 等）。
- **配置类** 类名统一 **`XxxConfig`**（如 **`AdminOpenApiConfig`**），替代 **`XxxConfiguration`**（框架 **`XxxAutoConfiguration`** 除外）。
- **不**为凑齐层次而新建空目录；无业务代码的模块保持精简。
- **禁止**仅为「模块看上去完整」而新增 **空 `*ModuleMarker`** 占位类；Bean 装载依赖 **`@Component` / `@Configuration`** 与 **`scanBasePackages`** 即可。

## 9. 本地基础设施

本地开发依赖 **PostgreSQL**、**Redis**；对象存储 **MinIO / AIStor** 另行本地部署（见下）。

### 9.1 `docker-compose.yml` 范围（website-services）

仓库内 **`services/website-services/docker-compose.yml`** **仅包含 PostgreSQL 与 Redis**。  
**MinIO 暂不并入该 Compose**：继续在 WSL/Docker 中 **单独部署**（或使用既有实例）。**阶段 4B Admin 认证**实现的主线依赖为 **PostgreSQL + Redis**，不因对象存储增加 Compose 前置。**MinIO** 计划在 **媒体资源与文件上传阶段**再纳入业务主线（届时可增补 Compose 或统一编排）。

### 9.2 默认端口与配置占位

本地常见端口：

- PostgreSQL：`localhost:5432`
- Redis：`localhost:6379`
- MinIO / AIStor API：`http://localhost:9000`（**非 Compose 默认项**，按需自行拉起）
- MinIO / AIStor Console：`http://localhost:9001`

`admin` 与 `site-app` 通过 `application-local.yml` 接入本地基础设施：

- `spring.datasource.url` 默认 `jdbc:postgresql://localhost:5432/my_website_dev`
- `spring.data.redis.host` 默认 `localhost`
- `spring.data.redis.port` 默认 `6379`
- `storage.minio.endpoint` 默认 `http://localhost:9000`
- `storage.minio.bucket` 默认 `uploads`

敏感信息通过环境变量注入，不在仓库中写入生产凭据。

## 10. 运行与验证

构建：

```bash
mvn clean install -DskipTests
```

启动：

```bash
mvn -pl gateway -am spring-boot:run
mvn -pl admin -am spring-boot:run
mvn -pl site/site-app -am spring-boot:run
```

验证：

- `GET http://localhost:8080/api/admin/ping`
- `GET http://localhost:8080/api/site/ping`
- `GET http://localhost:8081/api/admin/ping`
- `GET http://localhost:8082/api/site/ping`
- `GET http://localhost:8080/actuator/health`
- `GET http://localhost:8081/actuator/health`
- `GET http://localhost:8082/actuator/health`
- `GET http://localhost:8081/swagger-ui/index.html`
- `GET http://localhost:8082/swagger-ui/index.html`

说明：**`gateway` 未接入 springdoc-openapi**；OpenAPI/Swagger 仅在 **`admin`**（8081）与 **`site-app`**（8082）。

测试：

```bash
mvn test
```

持久层真实 PostgreSQL 回归（专用验证库、`verify-pg`、Maven Profile **`persistence-verify-pg`**）：

```bash
cd services/website-services
mvn clean test -Ppersistence-verify-pg -pl admin,site/site-app -am
```

详见：[持久层真实 PostgreSQL 验证说明](../数据文档/持久层真实PostgreSQL验证说明.md)。
