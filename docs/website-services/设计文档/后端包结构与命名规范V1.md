# 后端包结构与命名规范 V1（website-services）

**适用范围：** `services/website-services/` 下全体 Java/Spring Boot 模块。  
**目标：** 以「Maven 界定业务边界 + 模块内常规职责目录」保持长期可维护，避免 **`auth`** / **`admin`** 再次按业务域名拆二级树、避免 **`dto` 多级子目录与混名**、避免 **`Outcome`/`Summary`/`Result`** 等与 **`RequestDto`/`ResponseDto`** 并行的多套口径漂移。  
**与阶段关系：** **不改**阶段 4A 认证技术方案边界；本节仅约束 **代码组织方式**。

---

## 1. `common` 模块边界（最高优先级）

### 1.1 允许进入 `common` 的类型

仅限 **跨模块真复用**、且 **不包含具体业务契约** 的基础能力：

- 全局统一外壳：**`ApiResponse<T>`**
- 通用错误码 / 枚举：**`ErrorCode`**（及各模块共用的离散码值扩展方式）
- 通用异常：**`BusinessException`**（或对 `RuntimeException` 的薄封装基类）
- 通用分页 / 分页结果（若已形成稳定复用面）：本项目当前为 **`PageResult`**；若未来新增 **`PageRequest`**，须确有多模块消费再落 `common`
- 与业务无关的基础设施型工具（慎用）：需在文档与代码注释中写明 **被哪些模块复用**

### 1.2 禁止进入 `common` 的类型

**不得**下沉任何 **具体 REST 契约**：

- ❌ **`AdminLoginRequestDto` / `AdminLoginResponseDto`** 等 **`admin`** 专有 DTO
- ❌ **`Site*` 请求/响应**、`**Car*`、`Cake*`** 等板块契约
- ❌ 「未来也许 site 也用」的假复用：**先放业务模块**，重复出现再上收

### 1.3 组合示例（正确）

返回类型 **`ApiResponse<AdminLoginResponseDto>`**：外层 **`ApiResponse`** 出自 **`common`**，**`AdminLoginResponseDto`** 出自 **`admin/dto`**。

---

## 2. 模块内一级目录（Spring Boot 职责）

以下 **一级包名** 为允许的常规目录（**按需存在**，不强求全齐）：

`config`、`controller`、`service`、`mapper`、`entity`、`dto`、`handler`、`security`、`exception`、`utils`、`properties`、`constant`、`filter`、`interceptor`、`context`、`token`。

### 2.1 禁止的旧一级分层

禁止使用 **`interfaces`、`infrastructure`、`application`、`domain`、`po`** 等业务或 DDD 风格一级包。

### 2.2 禁止的「深层业务树」示例

除非经架构评审并形成书面例外说明，禁止：

- ❌ **`auth/admin`**、**`auth/site`**、**`auth/shared`**
- ❌ **`admin/auth/session`** 等深层业务树
  
**Spring Security 认证链路（过滤器、未登录 / 无权限入口）：** **`admin`** 等业务模块中使用 **`security/`**（如 **`AuthContextSynchronizingFilter`**、**`AdminAuthenticationEntryPoint`**、**`AdminAccessDeniedHandler`**），并由 **`config.AdminSecurityConfig`** 编入 **`SecurityFilterChain`**；**`handler/`** 仅承载 **全局异常**（如 **`GlobalExceptionHandler`**），与 Security 专有组件区分开。

骨架类模块（**`site-car` / `site-cake` / `config`** 子域等）在多级分包上允许 **占位式**结构，但一旦进入真实业务迭代，应逐步 **向上述一级职责目录收口**。

## 3. 父目录 → 类名后缀

| 目录 | 后缀 | 示例 |
|------|------|------|
| `config` | `XxxConfig` | `AdminSecurityConfig` |
| `controller` | `XxxController` | `AdminAuthController` |
| `service` | `XxxService` | **接口**占位：`AdminAuthService`、`AdminRefreshCookieService`、`AdminRefreshSessionService`；**实现类**统一在 **`service.impl`**，后缀 **`XxxServiceImpl`**（见 §6） |
| `mapper` | `XxxMapper` | `AdminUserMapper` |
| `entity` | `XxxEntity` | `AdminUserEntity` |
| `handler` | `XxxHandler` | **`GlobalExceptionHandler`**（REST 全域异常）；**不要**再放 Spring Security 的 **`AuthenticationEntryPoint` / `AccessDeniedHandler`**——见 **`security`** 行 |
| `security` | 按 Spring 接口或约定名 | `AuthContextSynchronizingFilter`、`AdminAuthenticationEntryPoint`、`AdminAccessDeniedHandler` |
| `exception` | `XxxException` | （业务例外：多数用 `common.BusinessException`） |
| `utils` | `XxxUtils` | **仅限**静态、无 `@Component` / 无配置注入的工具 |
| `properties` | `XxxProperties` | `JwtProperties`、`AdminAuthProperties` |
| `constant` | `XxxConstants` | `JwtClaimConstants` |
| `filter` | `XxxFilter` | 仅限 **通用 Web 过滤器**；**Admin JWT 上下文同步过滤器**归宿见 **`security.AuthContextSynchronizingFilter`** |
| `interceptor` | `XxxInterceptor` | — |

**说明：** Spring Security 中 **`AuthenticationEntryPoint`** /**`AccessDeniedHandler`** 的官方类型名不包含 `Json`。**推荐**与本项目 JSON 语义一致的 **`AdminAuthenticationEntryPoint` / `AdminAccessDeniedHandler`**，并与 **`security/`** 同包归档，避免与 **`handler.GlobalExceptionHandler`** 混放。

---

## 4. `dto` 目录规范（压平：`com.example.module.dto`）

业务模块 **`dto`** **不再**拆分 **`request` / `response` / internal** 子包；所有 DTO **直接放在**模块根 **`dto`** 包下 **（一级压平）**，用 **后缀**区分用途。

### 4.1 命名（统一以 `Dto` 结尾）

| 用途 | 命名 |
|------|------|
| HTTP 接口请求体 | **`XxxRequestDto`** |
| HTTP 接口响应体（或可序列化快照） | **`XxxResponseDto`** |
| 响应内部嵌套结构（或认证流程内部传递的非 HTTP Body 顶层类型） | **`XxxDto`** |

### 4.2 禁止扩散

- **`dto/`** 下禁止再使用 **`XxxRequest`（无 `Dto`）**、**`XxxResponse`（无 `Dto`）**、**`XxxOutcome` / `XxxSummary` / `XxxPayload`** 等与上述口径并行的多套后缀。
- **Sealed interface** 等在认证内部传递的类型（例如 **`RotateRefreshDto`**）：仍放在 **`dto`** 根包，后缀 **`Dto`**。

---

## 5. `utils` 规范

允许写入 **`utils`** 的类必须同时满足：

- **纯静态**方法为主（或仅存 **无状态的 `final`** 私有构造工具类）
- **不是** Spring **`@Bean`/`@Component`**
- **不显式注入** **`@Autowired`/`Environment`/`*Properties***

若逻辑依赖 **`AdminAuthProperties` / `JwtProperties`** 或其它配置：**不得**起名 **`XxxUtils`**，应归为 **`service.XxxService`**（或极小范围的 **`properties` 绑定类 + `@Service`** 编排）。

---

## 6. `service` / `service.impl` 规范（本项目定案）

- **`service/`**：**只放接口**（**`public interface XxxService`**）。**不写** **`@Service`**、**不写**默认方法承载业务流程（避免伪接口）。
- **`service.impl/`**：**只放实现类**，类名 **必须** 为 **`XxxServiceImpl`**，并 **`@Service`/`@Component`** 等按需标注；**多套生产实现**（如 **`RedisAdminRefreshSessionServiceImpl`**）也通过条件装配挂载到同一 **`XxxService` 接口**下。
- **调用方**：**`Controller`** 与其它 **`Service`** **必须依赖接口**，**禁止**字段类型写死 **`XxxServiceImpl`**。
- **测试替身**：**不允许**为单测在生产 **`main`** 混入内存实现。**在 **`src/test/java`** 提供 **`InMemory…ServiceImpl`**（或与生产对称的命名），经 **`@TestConfiguration`**（如 **`AdminRefreshSessionTestBeans`**）+ **`@Import`** 显式注册。

---

## 7. `auth` 模块边界

仅承载：

- JWT 对称签发的 **装配与实现**（**`AuthConfig`** + **`JwtBeansEnabledCondition`** + **`JwtTokenService`**）
- **`JwtProperties`、`TokenAudience`、`TokenClaims`、`TokenService`**
- **`AuthContext`、`AuthenticatedUser`、`AuthenticatedUserUtils`**
- **不透明 Refresh 随机串生成器 `RefreshTokenGenerator`**

严禁：

- Admin/Site **登录业务流程** / **会话持久化 Redis 细节** / **Cookie 拼装**
- **`security.auth.*` 前缀绑定类**（归属 **`admin.properties.AdminAuthProperties`**）
- **`auth`** 内部的 **`admin`** / **`site`** / **`shared`** 分包

---

## 8. Cursor / Copilot / 手动编码前置检查清单（可复制）

生成或移动 Java 代码前逐项自问：

1. 这是 **REST 契约** 吗？若是 → **`dto`** 根包 **`XxxRequestDto`/`XxxResponseDto`**，不要放 **`common`**。  
2. 这是 **纯算法/格式化**、零 Spring 依赖吗？若是 → 才考虑 **`utils`**。  
3. 这是 **业务流程编排**吗？若是 → **`service`**，后缀 **`Service`**，不要静态伪工具类。  
4. **`service` 是否要落实现代码？若是 → 放在 **`service.impl`**，命名 **`XxxServiceImpl`**，**不要在 `service/` 混入具体类**。  
5. **`auth`** 里是否又出现了业务分包名？—— **立即回迁** 对应业务模块。
