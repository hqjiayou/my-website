# 阶段 4H.0：请求链路日志与 Token 错误响应完善

> **文档状态**：当前有效（与实现对齐）  
> **最近同步**：2026-05-18  
> **阶段关系**：在进入或并行于 **阶段 4H（Gateway 全链路联调验收）** 前，补齐**可观测性与 Resource Server 错误体一致性**，不扩展业务语义、不改登录契约与 JWT Claims。

---

## 1. 背景问题

1. **请求链路不完整**：Gateway 仅能粗粒度观测请求进出；Auth / Admin 等服务缺少与网关一致的链路标识与访问日志，难以用同一 ID 串联 **Gateway → Auth / Admin**。  
2. **Token 无效时响应体不完整**：OAuth2 Resource Server 在 Bearer JWT 校验失败路径上默认可能只下发 **`WWW-Authenticate`**，**无**项目统一的 JSON 信封（含 i18n **message**、与未认证一致的 **code**）。

---

## 2. RequestId 设计

- **Header**：统一 **`X-Request-Id`**（常量见 **`com.mywebsite.common.web.HttpRequestCorrelation#X_REQUEST_ID`**）。  
- **Gateway**：入站若有则沿用，无则生成 UUID；**写入下游请求头**并与**响应头**回写。  
- **Servlet（Auth / Admin / site-app）**：infra 层 **`RequestLoggingFilter`** 读入 `X-Request-Id`，无则生成；**响应回写**；并将 ID 放入 **MDC**（键 **`requestId`**，见 **`HttpRequestCorrelation#MDC_REQUEST_ID`**），供安全事件等日志复用。  
- **直连服务**：不经过网关时仍生成/回写，保证单机排障可用。

---

## 3. 各层日志职责

| 组件 | 职责 |
|------|------|
| **Gateway** | 现有 **`RequestIdGatewayFilter`** 增强：请求结束后 **INFO** 打印 `gateway access requestId=… method=… path=… route=… status=… costMs=…`；不打印 body、Authorization、Cookie、Token、密码。 |
| **infra / Servlet** | **`RequestLoggingFilter`**：`{spring.application.name} access requestId=… method=… path=… status=… costMs=…`；仅 Servlet 应用注册，**不**用于 WebFlux Gateway。 |
| **Auth 安全事件** | 登录成功/失败、刷新成功、刷新重放检测、登出成功等 **INFO** 日志（见实现类中的 `auth security …` 前缀）；**禁止**记录明文密码、哈希、Access/Refresh Token、Cookie 原文。 |

---

## 4. 敏感字段与日志禁区

- **禁止**在访问日志或安全日志中输出：密码、密钥、Access/Refresh Token、Cookie 原文、Authorization 头。  
- **允许**在受控场景记录：`requestId`、`realm=admin`、成功后的 **userId**、失败时的 **username**（登录失败尝试名，便于审计；**不**记录密码）。

---

## 5. 401：未认证与 Token 无效的差异

| 场景 | HTTP | JSON `code` | `message` i18n key | `WWW-Authenticate` |
|------|------|-------------|--------------------|----------------------|
| 未携带 Bearer / 非 invalid_token 类未认证 | 401 | 与 **`ErrorCode.UNAUTHORIZED`** 一致（如 **1002**） | **`auth.unauthorized`** | 按 Spring/EntryPoint 行为；**不**伪造 invalid_token |
| Bearer 存在但 JWT 无效（验签失败、格式错误等，识别为 Bearer 无效原因链） | 401 | **同上 1002**（与未认证数值一致，符合既有体系） | **`auth.token.invalid`** | **必须**保留 **`Bearer error="invalid_token"`** 及规范描述（由 **`OauthResourceServerUnauthorizedSupport`** 与异常链配合） |

**403 权限不足**：仍由 **`AdminAccessDeniedHandler`**（及 Site 侧等价类）处理，**`messageKey`** 为 **`auth.access.denied`**，与 401 场景**不合并**。

---

## 6. WWW-Authenticate 保留原则

- Invalid bearer 场景下，**不得**因写入 JSON body 而丢弃 **`WWW-Authenticate: Bearer error="invalid_token"…`**。  
- 实现要点：在 **`AdminSecurityConfig` / `SiteSecurityConfig`** 中对 **`oauth2ResourceServer(…).authenticationEntryPoint(...)`** 显式绑定自定义 **`AuthenticationEntryPoint`**，使 JWT 过滤器链上的失败也进入 **`AdminAuthenticationEntryPoint`**（或 Site 侧 **`SiteAuthenticationEntryPoint`**），从而既能写 **JSON**，又能按 **`OauthResourceServerUnauthorizedSupport`** 补全挑战头。

---

## 7. i18n

- **`auth.token.invalid`** 放在 **common** bundle（**`common/src/main/resources/i18n/common/messages*.properties`**），避免 Admin 资源服务依赖 Auth 的 message 包。  
- **`auth.unauthorized`** 维持「未携带/未建立认证」语义，与「令牌无效」区分。  
- 语言示例：**ja** 默认条、`zh_CN`、`en_US` 同步维护。

---

## 8. 测试范围（摘要）

- **Gateway**：`RequestIdGatewayFilterTest` — 透传 / 生成 **X-Request-Id**、响应头。  
- **infra**：`RequestLoggingFilterWebIntegrationTest` — 直连风格请求、MDC、响应头。  
- **Admin**：`AdminPingSecurityMvcTest`、`AdminSecurityHandlersI18nTest` — 无 Bearer、非法/篡改 JWT（**WWW-Authenticate** 含 **invalid_token**）、多语言 **Accept-Language**、合法 Token **200** 回归。

---

## 9. 与后续 4H 的关系

本阶段**不**替代 **4H** 的「多进程 + 网关」业务验收，但提供：统一 **RequestId**、各层访问日志、Resource Server **401** 可理解的 JSON + 标准 **WWW-Authenticate**，降低全链路联调与生产排障成本。
