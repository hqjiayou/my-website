# website-services Java 持久层设计 V1

阶段：**3A 已正式关闭**（含 4 条收口修订，见正文 §4.4 / §5.2 / §5.6 / §6 / §8）；**3B 已完成**（`entity` + `mapper` + MP 基础配置 + 冒烟测试；**阶段 3 前置**已统一为常见 Spring Boot 包名与 `XxxEntity` 命名）  
前置：**阶段 2B 已关闭**（Flyway V1、数据字典、`数据库模型设计V1.md`、真实 PostgreSQL 迁移验证已完成）

本文档约定 Java 持久层的企业级规范；**DDL 不因 Java 调整**，若需改表仍走 Flyway + 数据文档三线同步。

## 1. 设计目标

| 目标 | 说明 |
| --- | --- |
| 与数据字典对齐 | Java 字段语义以 `docs/website-services/数据字典/` 与 Flyway DDL 为准 |
| 分层清晰 | **Entity** 止于持久映射；不把数据库行对象透出到 HTTP |

## 2. 当前前置条件

- PostgreSQL，`bigint identity`，`deleted` 软删除，`version` 乐观锁，`TIMESTAMPTZ` 审计时间。
- Flyway 脚本：`services/website-services/infra/src/main/resources/db/migration/V1__init_platform_core_tables.sql`（打包路径 `classpath:db/migration`）。
- 首批 8 表：`site`、`admin_*`、`site_user`、`site_user_profile`。
- `created_at` / `updated_at`：**以数据库 `DEFAULT now()` + `fn_touch_updated_at` 触发器为最终事实来源**；**MetaObjectHandler 不填充**（见 §4.4、§6）。

## 3. Entity（数据库映射实体）与 DTO 边界

### 3.1 Entity 定义

在本项目中，**Entity** 指与 **数据库表结构直接映射** 的 Java 类，位于各模块 **`entity`** 包下，供 **MyBatis-Plus** 使用；**不得**直接作为 Controller 的请求或响应类型。

**命名：`XxxEntity`（后缀 `Entity`）**

| 备选 | 评价 |
| --- | --- |
| `*Po` / `XxxPo` | **已废弃**（历史命名） |
| **`XxxEntity`** | **推荐**：与常见 Spring Boot 项目习惯一致 |

约定示例：`SiteEntity`、`AdminUserEntity`、`SiteUserEntity`。

**放置**：`**entity**` 包（如 `com.mywebsite.admin.entity`、`com.mywebsite.site.entity`）。公共审计基类：`com.mywebsite.infra.entity.AbstractAuditableEntity`。

**约束**：

- 与表 **一一映射**（含逻辑删除字段、版本号）。
- **不**作为 Controller 返回体或开放 API 契约。
- **不**等同于富领域模型；无业务规则、无聚合行为（首批阶段）。

### 3.2 领域模型（可选）

**明确推荐（首批 / 3B）：**

- **不为 8 张基础表逐一建立「富领域模型」**（无聚合行为、无领域事件阶段）。
- **阶段 3B 仅落地 `Entity` + `Mapper`**（见 §10）；业务编排暂以 **`service` 包 + `dto`** 为主。
- **何时引入富领域模型**：当出现明确不变式、跨表一致性规则或领域语言强于表结构时，再在 **专用包**（如业务子域下的 `model`）增补，并由 Converter 与 **Entity** 转换。

**结论**：**当前阶段不首批引入与表 1:1 的富领域模型**；避免 Entity/DTO/领域模型三重映射在未开展业务前过度膨胀。

### 3.3 DTO

| 类型 | 建议归属 | 说明 |
| --- | --- | --- |
| 入参 / 出参（HTTP） | **`dto` 包**：优先 **`XxxRequest` / `XxxResponse`**（避免泛泛的 `XxxDto`） | 面向传输契约 |
| 用例级组装对象 | **`dto` 或 `service` 包** | 跨端口编排、批量读写意图 |

**DTO 定义**：位于 **`dto`** 包，用于接口入参、出参或应用层数据传输；类名优先 **`XxxRequest` / `XxxResponse`**。

**禁止**：直接用 **`XxxEntity`** 作为对外请求体或响应体。

## 4. 公共基类设计

### 4.1 是否统一基类

**推荐：所有首批 8 表对应 `Entity` 均继承同一抽象基类**（关联表在库中同样具备完整审计字段，与 DDL 一致）。

建议类名：**`AbstractAuditableEntity`**。

**放置模块**：**`infra`**（依赖 **`mybatis-plus`** 注解 `@TableLogic`、`@Version`；**`common` 当前无 MP 依赖，不宜放带注解的基类**）。

**包路径（已定）**：**`com.mywebsite.infra.entity.AbstractAuditableEntity`**。

**作用域**：各业务模块中的 **`XxxEntity`** **继承**该基类；**`site-core`** 承载 `site` / `site_user` / `site_user_profile` 的 Entity 时，需在 **`site-core/pom.xml` 增加对 `infra` 的依赖**；**`admin` 已依赖 `infra`**。

### 4.2 是否拆分软删除 / 乐观锁

**首批不拆子接口**；同一基类包含：

- `Long id`
- `OffsetDateTime createdAt`、`Long createdBy`
- `OffsetDateTime updatedAt`、`Long updatedBy`
- `Boolean deleted`、`OffsetDateTime deletedAt`
- `Integer version`

理由：与当前 DDL 完全一致，减少泛型与继承层次；未来若有无 `version` 的只读同步表再拆无版本基类。

### 4.3 关联表

**沿用同一基类**（与 `admin_user_role` 等表结构一致）。

### 4.4 与 MetaObjectHandler 配合（3B 落地要点）

**时间字段（与 DDL 一致）**

| 字段 | 事实来源 | Java `MetaObjectHandler` |
| --- | --- | --- |
| `created_at` | 插入时 **DB `DEFAULT now()`** | **不填充** |
| `updated_at` | **INSERT 默认值** + **`BEFORE UPDATE` 触发器** `fn_touch_updated_at` | **不填充** |
| `deleted_at` | 业务删除用例再写入 | **3B 不自动填充**；后续删除服务显式赋值 |

**操作人字段**

| 字段 | 策略 |
| --- | --- |
| `created_by` / `updated_by` | 仅由 **`MetaObjectHandler`** 尝试写入（从未来 `AuthContext` / 解析器取当前用户 id）；**当前无登录态时允许跳过，保持 `null`** |

**其余**

| 字段 | 策略 |
| --- | --- |
| `deleted` | 逻辑删除由 **MyBatis-Plus `@TableLogic`** 维护（见 §5.2） |
| `version` | **`@Version`** + 乐观锁插件；插入时由 DB 默认 `0` / MP 处理 |

## 5. MyBatis-Plus 映射规范

### 5.1 主键

| 项 | 推荐 |
| --- | --- |
| Java 类型 | **`Long`** |
| 注解 | `@TableId(type = IdType.AUTO)` |
| 说明 | 对应 PostgreSQL **`GENERATED BY DEFAULT AS IDENTITY`**；插入不传 id 交由 JDBC/驱动分配 |

### 5.2 逻辑删除

数据库：`deleted BOOLEAN NOT NULL DEFAULT FALSE`。

| 项 | **已定方案（3B 写死）** |
| --- | --- |
| Java 字段 | `Boolean deleted` |
| 注解（落在 **`AbstractAuditableEntity.deleted`**） | **`@TableLogic(value = "false", delval = "true")`** |
| 全局 `logic-delete-field` | **不使用**；与注解二选一的模糊表述已取消，**以基类字段注解为准** |
| `deletedAt` | **不自动填充**；删除用例上线时显式写入 |

**说明**：`value` / `delval` 与 PostgreSQL `boolean` 字面值一致，逻辑删除更新为 `deleted = true` 时由 MP 生成。

### 5.3 乐观锁

| 项 | 推荐 |
| --- | --- |
| 注解 | **`@Version`** 作用于 `version` |
| 插件 | 注册 **`OptimisticLockerInnerInterceptor`**（配置类置于 **`infra`** 或与数据源同模块） |

### 5.4 命名映射

| 项 | 推荐 |
| --- | --- |
| 下划线 ↔ 驼峰 | **全局开启** `map-underscore-to-camel-case`（项目已约定） |
| `@TableField`** | 仅在例外字段（关键字、枚举入库）上使用；常规字段依赖全局映射 |

### 5.5 表名与 Schema

- 默认 **`@TableName("site")`** 等小写表名显式写出，避免重构类名误映射。
- 首批 **`public`** schema，不写 schema 前缀。

### 5.6 PostgreSQL `TIMESTAMPTZ` → Java 类型

**推荐：`java.time.OffsetDateTime`**

| 备选 | 说明 |
| --- | --- |
| `Instant` | 可做内部 UTC，但与 JDBC/MyBatis 部分场景需额外类型处理器 |
| `LocalDateTime` | **不推荐**：丢失偏移信息，与 `TIMESTAMPTZ` 语义不完全对齐 |

约定：**全项目持久层与时间戳字段统一 `OffsetDateTime`**（必要时 API 层再转换为展示时区）。

**语义（重要）**

- `OffsetDateTime` 在本项目中表示 **绝对时间点**（与库中 `TIMESTAMPTZ` 一致，一般为 UTC 或会话时区写入后的实例）。
- **不**将 `TIMESTAMPTZ` / `OffsetDateTime` 当作「保留用户原始本地时区」的载体；若未来需要门店时区、用户偏好时区，应在业务表中 **另行设计** `timezone` / `zone_id` 等字段（如 `site_user_profile.timezone` 仅为**偏好字符串**，不等价于审计时间语义）。

## 6. 审计字段与自动填充

**实现位置**：`**infra**` 模块提供 **`MetaObjectHandler`** Bean（实现类 `com.mywebsite.infra.handler.AuditMetaObjectHandler`；在引入 `infra` 的应用中生效，如 **`admin`**、**`site-app`**）。可选 **`com.mywebsite.infra.context.CurrentUserIdSupplier`** 用于解析当前用户 id。MyBatis-Plus 插件配置类：**`com.mywebsite.infra.config.MybatisPlusInfraConfig`**；对象存储相关：**`com.mywebsite.infra.config.StorageConfig`**。

**已定策略（与 §4.4 一致）**

- **不**对 `createdAt`、`updatedAt` 做 `insertFill` / `updateFill`；插入、更新后的时间列以 **`DEFAULT now()`** 与 **`fn_touch_updated_at`** 为准。
- **仅**预留对 **`createdBy`、`updatedBy`** 的填充逻辑（例如从未来统一解析器取当前用户 id）；**解析器无用户时字段保持 `null`**（3B 可为空实现）。
- **`deletedAt`**：不在 3B 自动填充。

## 7. Mapper 与 Repository 边界

### 7.1 Mapper

| 项 | 约定 |
| --- | --- |
| 位置 | 各模块 **`mapper`** 包（示例：`com.mywebsite.admin.mapper`） |
| 接口 | **`extends BaseMapper<XxxEntity>`** |
| 注解 | `@Mapper` |
| XML | **首批可无 XML**；复杂查询再到 **`classpath*:/mapper/**/*.xml`** |

### 7.2 Repository

**阶段 3B 稳妥策略：**

- **不强制实现 `Repository` 接口**。
- **Service** 层 **不直接暴露 Mapper** 的长期目标不变，但 **可采用渐进式**：
  - **3B**：允许 **仅通过封装薄层**（如 `SitePersistenceGateway` / `SiteRepositoryImpl`，放在 **`service` 或与持久化相邻包**）委托 Mapper；Repository 接口若存在，可在 **`repository` 包**定义，**首轮可为空**。
  - **推荐一句话**：**3B 优先完成 Entity + Mapper + 全局 MP 配置；Repository 接口可在首个真实业务用例引入时再抽取**。

**禁止**：在 **`controller`** 直接注入 Mapper。

## 10. 阶段 3B 落地清单（最稳妥）

建议在 **3B** 完成下列编码（**不写 Controller / 不写业务 CRUD Service**）：

| 序号 | 交付物 | 模块 |
| --- | --- | --- |
| 1 | **`AbstractAuditableEntity`**（含 DDL 对齐字段 + `@TableLogic` + `@Version`） | **`infra`**（包路径 **`com.mywebsite.infra.entity`**） |
| 2 | **MyBatis-Plus**：**仅** **`MybatisPlusInterceptor` + `OptimisticLockerInnerInterceptor`**（**`MybatisPlusInfraConfig`**） | **`infra`** |
| 3 | **`MetaObjectHandler`**（**`AuditMetaObjectHandler`**；仅 `createdBy` / `updatedBy`） | **`infra`** |
| 4 | **8 个 `XxxEntity`** + **`@TableName`** | **`admin`** / **`site-core`** 按 §8 |
| 5 | **8 个 `XxxMapper extends BaseMapper<XxxEntity>`** | 同上 |
| 6 | **`site-core/pom.xml`**：增加 **`infra`** 依赖 | **`site-core`** |
| 7 | **`admin/pom.xml`**：~~增加 site-core~~ **3B 不要求**（已取消） | **`admin`** |
| 8 | **冒烟**：`test` profile + 内存 H2；验证上下文 + **`MybatisPlusInterceptor`** + 各 **`Mapper`** Bean（**不**执行 CRUD） | **`admin`** / **`site-app`** |

**3B 明确不引入**：**`PaginationInnerInterceptor`**、**`mybatis-plus-jsqlparser`**（分页与动态表名解析本期不需要）。

**3B 暂不强制**：XML Mapper、Repository 接口与实现、Converter、整套 CRUD Service。

### 阶段 3B 已实现项（与仓库同步）

- **基类**：`com.mywebsite.infra.entity.AbstractAuditableEntity`；**保留** `createdAt` / `updatedAt` 与 DDL 映射一致；**不由** `MetaObjectHandler` 填充时间列。
- **逻辑删除**：`deleted` 使用 **`@TableLogic(value = "false", delval = "true")`**（唯一方案，见 §5.2）。
- **乐观锁**：`version` + `@Version`；**`MybatisPlusInterceptor`** 中**仅**注册 **`OptimisticLockerInnerInterceptor`**。
- **审计人**：`AuditMetaObjectHandler`（**`infra.handler`**）仅 **`createdBy`（INSERT）**、**`updatedBy`（UPDATE）**；无 **`com.mywebsite.infra.context.CurrentUserIdSupplier`** Bean 时跳过，**不**伪造用户 id。
- **表映射类**：`admin` 模块 5 Entity + 5 Mapper（**`admin.entity`** / **`admin.mapper`**）；`site-core` 3 Entity + 3 Mapper（**`site.entity`** / **`site.mapper`**）；均 **`extends BaseMapper<XxxEntity>`**、`@Mapper`，无 XML。OpenAPI：**`XxxConfig`**；全局异常处理：**`handler.GlobalExceptionHandler`**。
- **依赖**：**已** `site-core` → `infra`；**未** `admin` → `site-core`。
- **测试**：`admin`、`site-app` 的 **`src/test/resources/application-test.yml`**（H2 + 关闭 Flyway + 占位 MinIO 配置）+ **`@ActiveProfiles("test")`**，断言 **`MybatisPlusInterceptor`**、**`AuditMetaObjectHandler`**、全部 **`Mapper`** Bean。

**核验记录**：与本清单逐项对照的结论见 **[`阶段3B-持久层落地核验记录.md`](./阶段3B-持久层落地核验记录.md)**。

## 11. 与数据字典 / DDL 的关系

- Java 字段名与类型以 **`docs/数据字典/`** 与 Flyway DDL 为准；**本轮不改数据字典条目**。
- 若 3B 实现中发现 **DDL 缺陷**：必须先改 **Flyway（新版本脚本）** → **`数据库模型设计V1.md`** → **`docs/数据字典/`**，再改 Java；**禁止仅改 Entity 不改库**。

## 12. 风险与后续演进

| 风险 | 应对 |
| --- | --- |
| `admin` 暂时无法直接注入 `SiteMapper` | 待站点管理迭代再增加 **`admin` → `site-core`** 或防腐层 |
| `site-core` 引入 `infra` | 站点与用户持久化依赖数据源属预期；**`gateway` / `agent` 仍不引用 `infra`** |
| `deleted_at` 与 MP 逻辑删除不同步 | 删除用例显式写 `deletedAt`；后续可插件化 |
| 双应用共用 `site-core` | **`site-app`** 依赖 `site-core`；**`admin`** 3B 仅用自身 **Entity**；**勿**在 `auth` 引用业务 **Entity** |
| 领域模型滞后 | 业务复杂化后在专用包引入模型 + Assembler |
