# 阶段 4B 前置 · website-services 后端全量代码规范与链路审计

**审计日期：** 2026-05-17  
**审计范围：** `services/website-services/`（gateway / admin / agent / auth / common / config / infra / site-*）  
**规范依据：** 《架构设计.md》、阶段 4A 两份认证文档、`README.md`、`Java持久层设计V1.md`、`数据库模型设计V1.md`、`持久层真实PostgreSQL验证说明.md`、本轮前置约定（Spring Boot 职责目录 + 后缀、`auth`/`admin` 边界、阶段 4B 暂停扩功能）

---

## 1. 审计目标

对照已确认的目录与命名规范、模块边界与阶段边界，评估：

1. **文件夹 / 文件命名**是否与规范一致；
2. **是否存在废话代码 / 过度抽象**（占位、空转发、过早扩展）；
3. **基础链路**（配置、持久层、Redis、Swagger、测试、文档、4B 认证已实现部分）是否自洽；
4. **既有硬性要求**（禁止 DDD 一级包名、禁止 Po、Flyway 单一来源、Swagger 为字段权威等）是否落实。

本轮 **不**评价业务完备度（RBAC、Site 登录等仍在阶段边界之外）。

---

## 2. 审计范围与方法

- **代码：** 全模块 Java / 资源配置抽样与关键点定向检索（`*Helper*` / `*Outcome*` / `interfaces` / `infrastructure` / `auth/admin|site|shared` 包路径、`Flyway` 路径、`swagger` 依赖与路由文档对齐等）。
- **文档：** `docs/website-services/` 下架构、阶段 4A、持久层验证说明及与本工程交叉引用段落。
- **说明：** 不同检出工具对「未跟踪 / 仅索引」文件的可见性可能不一致；**以下结论以当前工作区可编译、`mvn test` 通过的树为准**，并以磁盘目录枚举复核 `auth` 包结构。

---

## 3. 总体结论

| 维度 | 结论 |
|------|------|
| **目录 / 命名** | **中等健康**。`admin` 侧 4B 认证代码已收敛到常规职责包；`auth` 曾存在 **空的 `admin`/`site`/`shared` 子目录**（边界漂移风险），本轮 **已删除**。仍存在少量 **后缀与「目录→后缀」表不完全同构** 的命名（见 §4、§5）。 |
| **废话代码 / 过度设计** | **整体可控**。`AdminRefreshSessionStore` + Redis / InMemory **有成体系的测试与降级语义**，不属于典型「空抽象」。`*ModuleMarker` 在当前磁盘快照下 **未发现残留文件**（与《架构设计》§8「禁止空 Marker」一致）。 |
| **基础链路** | **主线闭环**。默认 `mvn test` 可通过；Flyway **规范路径为 `infra`）、Swagger **仅在 admin/site-app**、Gateway **未聚合 OpenAPI** 与 README / 架构描述一致；持久层 PG 回归文档与 Surefire Tag 策略仍在，**本轮微调 admin 回归测试的包名**（见 §9）。 |
| **阶段边界** | **未发现**本轮扫描范围内新增 RBAC 业务代码、Site 登录、验证码、网关 JWT 校验、黑名单或 **新 Flyway 版本脚本**。 |

**综合判断：** 代码基线 **可保留**，优先 **精简命名与占位残留**，**不建议**为「洁癖」整体回退 4B；个别抽象是否进一步合并 **适合人工拍板**（§10）。

## 4. 目录与命名规范审计结果

### 4.1 禁止的业务深层包 / DDD 一级包

| 检查项 | 结果 |
|--------|------|
| `admin/auth/`、`admin/security/`、`admin/dto/auth/` | **未发现**（当前 admin 认证落在 `controller` / `service` / `dto` / `handler` / `filter` / `config` / `properties` / `constant` / `utils`）。 |
| `auth/admin`、`auth/site`、`auth/shared` | **曾存在空目录**（违反「不得在 auth 内再按业务域分裂」）；本轮 **已从磁盘移除**，当前 `auth` 下仅剩 **`config` / `context` / `principal` / `token`**。 |
| `interfaces`、`infrastructure`、`application`、`domain`、`po`（一级业务包） | **未发现**于扫描样本。 |

### 4.2 其它目录漂移（骨架模块）

以下 **不属于 4B 回归必修**，但与「极致扁平」略有张力，记入改进 backlog：

- **`site-core` / `site-car` / `site-cake`**：存在 `core/context`、`car/catalog`、`cake/order` 等 **多级骨架包**——当前主要为占位边界，尚未承载大量业务；是否在下一阶段统一扫平为「顶层职责目录」，由站点模块演进时再定。
- **`config` 模块**：`brand` / `layout` / `seo` / `theme` 等子包——符合「配置域分包」设想，但与 admin 的「单层职责目录」风格不一致；属 **模块个性**，不建议强行与 admin 对齐。
- **`infra`**：`entity`、`handler`、`context`、`properties`、`client`、`storage`、`datasource`、`redis`、`config` 并存——作为基础设施聚合模块 **合理**，不要求与业务模块目录表完全一致。

### 4.3 文件命名 vs 父目录后缀（重点）

**符合或基本符合**

- `AdminSecurityConfig`、`AdminOpenApiConfig`、`JwtProperties`、`AdminAuthSecurityProperties`
- `AdminAuthController`、`AdminPingController`、`AdminAuthService`
- `AdminAccessDeniedJsonHandler`、`GlobalExceptionHandler`、`AdminUnauthorizedAuthenticationHandler`（均落在 `handler`，后缀 `Handler`）
- `AuthContextSynchronizingFilter`（`filter`）
- `AdminRefreshCookieUtils`、`RefreshTokenHashUtils`（`utils`）
- `AdminAuthConstants`、`AdminAuthRedisKeyConstants`、`JwtClaimConstants`（常量）
- `*Mapper` / `*Entity` / `*Request|Response|Dto`
- `JwtTokenService` 实现 `TokenService`（`token` / `service` 语义分层清晰）

**与规范表「不完全同构」但可解释（建议 §10 选择性收口）**

| 位置 | 类 | 说明 |
|------|-----|------|
| `admin/service` | `AdminRefreshSessionStore`（接口）、`RedisAdminRefreshSessionStore`、`InMemoryAdminRefreshSessionStore` | 后缀 **`Store`** 而非 `Service`，但表达「会话存储」比硬改名为 `*Service` 更贴切；若强求后缀统一，需人工定口径。 |
| `admin/service` | `RotateRefreshDto`（`sealed interface`） | 命名 **`Dto`** 却放在 **`service` 包**，与「DTO 优先放 dto」的常见习惯不一致；可迁至 `dto` 或改名为内部 `RotateRefreshResult` 等并由人工取舍（避免与已废弃的 Result 泛滥口径冲突）。 |
| `infra/context` | `CurrentUserIdSupplier` | 后缀 **`Supplier`** 不在规范表中；职责是为审计字段提供可选当前用户 ID，**小而清晰**，可保留或改名为 `CurrentUserIdProvider` 等与 Spring 语义对齐。 |

**历史清单对照（用户关心的旧名）**

下列名称多数 **已完成收敛或不存在**：`AdminRefreshCookieHelper`→**Utils**、`AdminAuthRedisSchema`→**Constants**、`RotateRefreshResult`→**RotateRefreshDto**、`AdminAuthUserSummary`→**AdminLoginUserResponse**、`SecurityAuthProperties`→**AdminAuthSecurityProperties（admin）**、`AuthJwtBeansConfiguration`→并入 **`AuthConfig`**、`AuthenticatedUsers`→**AuthenticatedUserUtils**、`AccessTokenIssuance`→**IssuedAccessToken**、`JwtClaimNames`→**JwtClaimConstants**。审计结论：**命名漂移风险已从高点回落**，残余主要在 **`Store`/`Dto` 包位置** 与 **骨架多级包**。

### 4.4 `dto` 中 Cookie 相关类型

- `AdminLoginCookieDto`、`AdminRefreshCookieDto`：用于 **组装 HttpOnly Cookie + JSON Body**，避免 Controller 充斥 Cookie 细节；**未**使用 `Outcome`/`Payload` 等禁用后缀。**结论：** 合理，可在报告中注明设计意图即可。

## 5. 过度设计 / 「废话代码」审计结果

### 5.1 有明显价值的抽象

- **`AdminRefreshSessionStore` + Redis / InMemory**：对应 **「生产 Redis / 默认测试不强依赖本机 Redis」** 的既定策略；`InMemoryAdminRefreshSessionStoreTest`、集成测试路径与之匹配。**不建议**在未决策的情况下删除 Store 分层。
- **`JwtBeansEnabledCondition`**：`security.jwt.secret` 为空时不装配 JWT Bean，避免 **`site-app`** 等模块在密钥未配置时无法冒烟。**结论：** 属于 **真实约束**，不是为未来预留的空条件。

### 5.2 可合并或精炼的候选（非必须）

- **`RotateRefreshDto`**：体量很小；若团队更希望「减少类型个数」，可把 sealed 联合折叠进 **`AdminRefreshSessionStore` 返回单一私有静态类型**或迁至 **`dto`**——**影响可读性**，需人工权衡。
- **Cookie DTO 两层**：`AdminLoginCookieDto` / `AdminRefreshCookieDto` 与 JSON Response 拆分；若追求极简，可把 Cookie 写入迁入 **`AdminAuthService` 返回记录类型**——会增厚 Service，未必更清爽。

### 5.3 设计未要求但代码「多做」？

对照阶段 4A 文档与当前仓库：

- **未发现** Gateway JWT 校验、Access 黑名单、验证码、Site 登录完整链路、RBAC 权限判定等新阶段功能的大规模落地。
- **Admin** 已有阶段 3B 相关 **Entity/Mapper**（用户表 RBAC 骨架），属于 **早于 4B 的阶段产出**，不是本轮 4B 扩 scope；与「4B 只做认证闭环」 **不冲突**（认证仅用 `AdminUser` 基础字段）。

### 5.4 「AI 味」与注释

- 关键类（条件 JWT、`RotateRefreshDto`、持久层 PG 测试）注释 **适度**，未发现大范围冗余段落。**结论：** 可接受。

## 7. 阶段 4B 认证代码当前状态审计

### 7.1 链路闭合度（已实现）

```
security.* 配置（jwt + admin AdminAuthSecurityProperties）
  → AuthConfig（条件 Jwt Beans）/ JwtTokenService
  → AdminAuthService（口令、会话、签发 Access）
  → AdminRefreshSessionStore（Redis / InMemory）
  → AdminAuthController（login / refresh / logout）
  → AdminSecurityConfig（放行三接口 + JWT Resource Server）
  → Swagger（adminBearer）
  → JwtTokenServiceTest + InMemoryAdminRefreshSessionStoreTest + AdminAuthMvcTest
```

**结论：** **已形成闭环**，与设计文档 §18「阶段 4B 落地状态」 **一致**。

### 7.2 `auth` 边界是否漂移

| 检查项 | 结论 |
|--------|------|
| Admin Cookie / Redis Session / Admin DTO | **均在 admin**，未回流 auth |
| `auth` 分包 | **已无双业务空包**；源码为 **`config/context/principal/token`** |
| JWT 通用能力、`IssuedAccessToken`、`JwtClaimConstants`、`AuthenticatedUserUtils` | **留在 auth**，职责恰当 |

### 7.3 `admin` 边界是否漂移
