## 为什么题集独立于 golden_qa

现有 `run_answer_eval` 的 `_run_case` 调 `run_chat` 时不传 `skill_instructions`，runner 没有 skills 注入点；硬挂需要改 eval runner 的执行路径。本单按「挂不上就以独立题集文件＋说明落地」口径处理：题集独立成 `skill_qa.jsonl`，字段与 golden_qa 同风格（id/question/expected_behavior/expected_answer/expected_keywords），另加 `skill`（目标 skill）、`kind`（positive/negative/quality）与 `golden_ref`（与 #180 黄金集的对齐锚点，共 9 条带 ref）。若后续给 runner 加 skills 注入，此题集可直接被消费。

## 真模型层为何 BLOCKED 与本机跑法

沙箱内实测（2026-11-03）：

```text
$ python -m agent_services.evals.run_answer_eval
BLOCKED: answer quality eval did not run. AI model is not configured (missing AI_MODEL). Refusing to score with a fake model.

```

原因与 #180 相同：沙箱无 `AI_MODEL`/密钥，凭据纪律不许把连接器密钥注入独立进程。触发率/完成率不在沙箱内编造。

**本机跑法（kou 本机全栈，试聊 preview）**：逐题按 `evals/skill_qa.jsonl` 发送问题——

- positive/quality 题：试聊显式带 `skills: [<该题 skill>]`，核对响应 `skillsApplied` 含目标 skill、行为符合 `expected_behavior`（集合级题还应看到 todo 快照与枚举调用）、答案命中 `expected_answer`/`expected_keywords`。
- negative 题：显式带上题面所标 skill 发送，核对模型不强行套用该打法（如菜单价格题不调 `list_knowledge_documents`、公休题不调 `query_site_table`、单事实题不整篇总结）；同时按 catalog description 人工核对路由归属是否一目了然。
- 题量与调用量：17 题；positive/quality 题每题约 3–6 次 provider 请求（工具多轮），negative 约 2 次，预计总计约 **50–90 次请求**（与免费层额度同桶）。可按 skill 分批跑：cross-doc-aggregation 5 题约 20–30 次，其余各 4 题约 10–20 次。跑完把逐题结果回填 #182；触发/完成不达标先改 description/打法再测，不带病合入。
